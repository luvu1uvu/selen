# Правила вида Selen

Как выглядит интерфейс Selen: цвета, отступы, размеры, скругления, шрифт, состояния, тексты — в светлой и тёмной теме.
Файл собран 20.10.2026 из текущего кода (LATER-71, ADR-0023): токены `frontend/src/index.css`, компоненты
`frontend/src/shared/ui`, частоты классов Tailwind по `*.tsx`, раскладка досок (ADR-0019), тексты `locales/ru`. Новая
версия для двух тем — 26.10.2026, «Редизайн», шаг 2: направление «Линия» и тёмная тема (LATER-72, LATER-89, ADR-0025).
Он описывает, как уже сделано и как делать дальше; что сейчас расходится с правилами — раздел 12.

- **Раскладку и поведение** экранов задаёт README Kaiten (`docs/ui-reference/kaiten/README.md`): где что стоит и как
  себя ведёт — как в Kaiten. **Облик** (цвета, шрифт, значки, отступы) — свой, по этому файлу.
- **Значения** берутся из кода: токены — `index.css`, размеры компонентов — `shared/ui`. Здесь — какие из них где
  применять. Значение меняется в коде — меняется и строка здесь, в том же PR.
- **Кто сверяет:** сессия, которая делает экран; ревьюер подэтапа; агент `ux-reviewer` (`.claude/agents/`). Агент
  находит то, чего здесь нет, и предлагает дополнение — оно попадает сюда в PR с изменением интерфейса и принимается
  PM вместе с PR.

## 1. Основа

- **shadcn/ui** (стиль new-york), Tailwind 4, значки **lucide**. Новый элемент интерфейса — сначала готовый компонент
  `shared/ui` (или `npx shadcn add`, ловушка — CLAUDE.md), потом свой.
- **Две темы — светлая и тёмная** (ADR-0025). Токены — `index.css`: светлая — `:root`, тёмная — набор `.dark` (класс на
  `<html>`); `color-scheme` — на `html`, поэтому нативные поля даты, `select`, флажки и полосы прокрутки темнеют сами.
  Цвета компонентов — только смысловые токены (раздел 2): тема меняется одними значениями, компоненты не трогаются.
  `dark:` в компоненте — только когда в тёмной теме меняется приём, а не цвет (тени, раздел 5). На время смены темы
  переходы выключены (`theme-switching`) — цвета не «перетекают».
- **Выбор темы** — только в меню пользователя: группа «Тема» — «Светлая / Тёмная / Как в системе», по умолчанию
  «Светлая», у выбранной — галочка, меню после выбора не закрывается. Хранится в настройках пользователя на сервере,
  копия — в браузере; до загрузки кода тему ставит `/theme-init.js` — без вспышки светлой (ADR-0025).
- **Облик — направление «Линия»** (журнал `docs/stages/redesign.md`, прототипы `design/redesign/lines/`): всё очерчено
  тонкими линиями, плотность и скругления — как в Kaiten, акцент — сине-фиолетовый «индиго» в обеих темах. Запоминается
  одно: индиго-полоска у всего выбранного (раздел 7), остальное спокойно. В тёмной теме уровни — тоном: холст → доска →
  карточка светлее; главная кнопка — светлый акцент с тёмным текстом.
- Нативные переключатели (`radio`, `checkbox` в тексте) — `accent-color: var(--primary)` (base-слой `index.css`), а не
  синий цвет браузера.
- **Шрифт — системный** (стандартный `sans` Tailwind). Номер карточки и ключ пространства — тем же шрифтом с ровными
  цифрами (`tabular-nums`); моноширинный — только коды цвета (`#4f46e5`) в полях цвета и технические поля журнала событий.
- Единица шкалы — 4 px (`1` в Tailwind = 0,25rem). Произвольные значения (`p-[3px]`, `-left-[4.5px]`) — только с
  комментарием, почему не шкала.

**Решения PM, на которых стоит облик:**
- 21.10, по резюме `ux-reviewer` к LATER-89 (журнал — `docs/stages/later-91.md`): 1) полоса разделов — узкая, только
  значки, как в Kaiten; 2) колонки — доска-блок, колонки через тонкие линии, уровни тоном холст → доска → карточка
  (ADR-0019 не меняем); 3) название пространства — крупнее (`text-xl`), в той же строке; 4) полоса типа на карточке —
  не трогаем до этапа 7; 5) главная кнопка в тёмной теме — светлый акцент с тёмным текстом; 6) выбор темы — на сервере,
  копия в браузере; 7) переключатель «Светлая / Тёмная / Как в системе» — только в меню пользователя; 8) по умолчанию —
  «Светлая»; 9) сине-фиолетовый акцент — в обеих темах; 10) метки — свободный цвет, цвет текста автоматически (LATER-91);
  11) подготовка — LATER-91.
- 26.10, по шагу 1 «Редизайна»: направление «Линия»; шрифт системный; номер карточки — `tabular-nums`, не моноширинный;
  карточка в тёмной теме светлее доски; рамка фокуса — цветом акцента 2 px с отступом 2 px; граница полей — не меньше
  3:1 во всех темах; плотность — как сейчас; белая карточка на белой доске с тонкой рамкой — это и есть уровни.
- 26.10, по плану шага 2: смена темы в журнал событий не пишется; ключ пространства — тоже `tabular-nums`; скрипт темы —
  отдельным файлом, не встроенным (CSP `script-src 'self'`, LATER-86).

## 2. Цвета

Только токены: `bg-*`, `text-*`, `border-*`, `ring-*`, `outline-*` с именами из таблиц. Нужен новый смысловой цвет —
новый токен в `index.css` — в `:root`, `.dark` и `@theme inline`, а не цвет палитры в компоненте. Цвета палитры Tailwind
(`red-50`, `emerald-700`…) — только как значения токенов в `index.css`.

**Цвета данных** — одинаковы в обеих темах, поэтому не токены; живут в `shared/lib/palette.ts`:
- метки и типы карточек — цвет задаёт пользователь, любой (решение PM 21.10, LATER-89); готовые цвета выбора —

  оставить, WCAG 2 AA проходит;
- аватары — 8 цветов `AVATAR_COLORS`, инициалы белые, каждый цвет не меньше 4,5:1 с белым.

**Проверка — `make lint`, `make test` и CI.** Токены: `src/theme-tokens.test.ts` — у каждого цвета `:root` есть
значение в `.dark`, пары контраста раздела 11 не ниже нормы в обеих темах, в тёмной холст → доска → карточка светлеют;
новый цвет текста, значка или рамки — новой парой в этом тесте. Компоненты: ESLint `no-restricted-syntax`
(`frontend/eslint.config.js`; автотест — `frontend/eslint.config.test.ts`). Ошибка в любой строке компонента
(className, `cn()`, `cva()`, `style`):
- цвет палитры Tailwind с любым префиксом и прозрачностью — `bg-red-50`, `hover:text-emerald-700`, `dark:border-red-800`,
  `text-white`, `bg-black/50`;
- переменная палитры в обход класса — `bg-(--color-red-500)`, `[color:var(--color-emerald-700)]`;
- цвет функцией — `bg-[color-mix(…)]`, `shadow-[…rgba(…)]`, `boxShadow: '… rgba(…)'`;
- hex — `'#3b82f6'`, `bg-[#fff]`, `border: '1px solid #ddd'` (якорь вида `#add-button` — не цвет);
- рамка фокуса с прозрачностью — `ring-ring/50`, `outline-ring/50` (их приносит `npx shadcn add`).

Исключения: `shared/lib/palette.ts` (цвета данных), тесты (`*.test.*`, `src/test/**`) и одиночные строки с причиной —
`// eslint-disable-next-line no-restricted-syntax -- …`. Сейчас такая одна: `bg-black` под видео во вложениях (поля
вокруг видео чёрные в любой теме). `index.css` ESLint не проверяет — это файл токенов. Цвета, которые выбрал
пользователь, приходят в `style` переменной и проверку не задевают.

## 3. Отступы

Шкала, которая используется: **0.5 (2 px), 1 (4), 1.5 (6), 2 (8), 3 (12), 4 (16), 6 (24), 8 (32), 12 (48)**. Частота по
коду: `gap-2` — больше сотни мест, затем `gap-1`, `gap-4`, `px-2`, `px-3`, `gap-3`, `gap-6`, `gap-1.5`. Другие шаги
(`2.5`, `5`, `7`) — только внутри компонентов shadcn и для позиций значков в поле.

| Где | Отступ |
|---|---|
| Значок и текст в одной строке (кнопка, пункт меню, бейдж) | `gap-2` в кнопке и меню; `gap-1.5` в строке дерева и маленькой кнопке; `gap-1` в бейдже и на фасаде карточки |
| Кнопки в ряду, элементы в строке | `gap-2`; мелкие значки рядом — `gap-1` |
| Блоки внутри окна, формы, вкладок | `gap-4` (`DialogContent`, `Tabs`); заголовок и описание окна — `gap-2` |
| Разделы страницы | `gap-6`; заголовок страницы и пояснение под ним — `gap-1`/`gap-2` |
| Поля обычной страницы (`main`) | `p-4`, с 768 px — `p-8` |
| Окно (`Dialog`) | `p-6`; выезжающая панель (`Sheet`) — `p-4`; окно карточки — без своего поля, содержимое — `px-4 pt-5 pb-6`, с 640 px — `px-6`, секции — `gap-4` |
| Строка «название поля — значение» (окно карточки) | название — колонка 10rem (160 px), зазор `gap-4`; уже 640 px — название над значением; строки — `gap-2`; кнопка без фона в столбце значений и внизу секции — текст вровень с левым краем (`-ml-2` при `px-2`) |
| Меню | `p-1`; пункт — `px-2 py-1.5`; разделитель — `my-1` |
| Подсказка (`Tooltip`) | `px-3 py-1.5` |
| Бейдж | `px-2 py-0.5`; плотная метка на фасаде — `px-1.5` |
| Сообщение (`Alert`) | `px-4 py-3` |
| Ячейка таблицы | `p-2` |
| Холст досок | `p-3`, с 768 px — `p-4`; между досками ряда и между строками одного ряда — `gap-3`, между рядами — `gap-6`: ряд виден на экране (ответ PM 21.10) |
| Вкладки страницы пространства («Участники», «Метки») | как у холста: `p-3`, с 768 px — `p-4` — левый край вровень с названием на панели |
| Панель страницы пространства | `px-3 py-2`, с 768 px — `px-4`; группы (название, вкладки, кнопки) — `gap-x-4`, кнопки — `gap-2`; узкая панель (уже 56rem, container query) — группы `gap-x-1.5`, название · ключ · ⓘ — `gap-1`, вкладки — `px-1.5`, ключ — `px-1.5` |
| Блок доски | шапка, строка заголовков колонок, тело, полоса дорожки — по `px-3`; с ручкой ⠿ (страница пространства) название стоит в 43 px от края блока (`-ml-1` + `size-7` + `gap-1.5`), ручка — примерно вровень с названиями дорожек |
| Колонки | зазор `gap-2`, тонкая линия-разделитель — посередине зазора |
| Ячейка доски | `p-2`; карточки друг под другом — `gap-2` |
| Карточка на доске | `px-3 py-2`; строки внутри — `mt-1`/`mt-1.5` |
| Дерево | панель — `px-2 pt-1` (поле сверху — рамка фокуса первой строки не срезается, раздел 11); строки — `gap-0.5`; шапка — `px-4`; поиск — `px-3 pb-2`; деревья компаний (если их несколько) — `gap-2`, заголовок компании — `mt-2 h-8 pl-2`, `text-xs font-semibold uppercase` `muted-foreground`, «+» компании (`size-8`) — справа в заголовке; место «+» у поиска держится, пока дерево грузится (поле не «прыгает») |

Похожие элементы — с одинаковыми отступами: строки одного списка, ячейки одной доски, кнопки одного ряда. Левые
края текста в столбик совпадают. В блоке доски (замер 20.10): название доски и полосы дорожек — 12 px от края блока
(`px-3`); названия колонок — 20 px (`px-3` блока + `px-2` заголовка), вровень с левым краем карточек (`px-3` + `p-2`
ячейки).

## 5. Скругления, границы, тени

`--radius` = 0.5rem: `rounded-sm` 4 px, `rounded-md` 6 px, `rounded-lg` 8 px, `rounded-xl` 12 px.

| Скругление | Где |
|---|---|
| `rounded-sm` | пункты меню |
| `rounded-md` | кнопки, поля, бейджи, подсказки, меню, карточка на доске, строки дерева |
| `rounded-lg` | окна, сообщения (`Alert`), список вкладок, значки полосы разделов |
| `rounded-xl` | блок доски, `Card`, пустое место на пустой доске |
| `rounded-full` | аватары |

- **Граница** — 1 px, цвет `border`; у полей ввода — `input` (не меньше 3:1). «Линия»: блок доски, карточка, меню и
  окна очерчены в обеих темах — в светлой доска и карточка обе белые, карточку отделяет рамка. Пунктир — заглушка пустого
  места (пустая доска), место броска при переносе и пустое описание. Цветная полоса слева у карточки (`border-l-4`) — тип
  карточки.
- **Тени, светлая тема:** `shadow-xs` — кнопки, поля, флажки, карточки на доске (наведение карточки — `shadow-sm`);
  `shadow-sm` — `Card`; `shadow-md` — меню и всплывающие панели; `shadow-lg` — окна и перетаскиваемая карточка. Блок доски —
  без тени, только граница на фоне холста.
- **Тени, тёмная тема:** на тёмном тень не видна — у кнопок, полей, флажков, карточек на доске, `Card` и круглых кнопок
  окна карточки её нет (`dark:shadow-none`); карточку отделяют тон (светлее доски) и рамка, наведение — рамка светлее
  (`dark:hover:border-input/50`, у заблокированной рамка не меняется). Меню и окна — свой фон (`popover`; окно —
  `background`) и рамка `border`; их тень остаётся (тёмная, на затемнении не мешает).

## 6. Шрифт

| Размер | Где |
|---|---|
| `text-2xl font-semibold` | заголовок страницы (`h1`) |
| `text-xl font-semibold` | заголовок экрана ошибки; название пространства на панели страницы пространства — в той же строке (решение PM 21.10, п. 3) |
| `text-lg font-semibold` | заголовок окна |
| `text-base font-semibold` | название доски в шапке блока, заголовок панели дерева |
| `text-sm` (14 px) | основной текст интерфейса: кнопки, поля, меню, строки, карточки; заголовок секции окна карточки — `text-sm font-semibold`; название поля в «Основных параметрах» — `text-sm text-muted-foreground` обычной насыщенности (`<Label>` в строке — `font-normal leading-5`) |
| `text-xs` (12 px) | вторичное: счётчики, номер карточки, метаданные, бейджи, подсказки, полоса пустого дерева |
| `text-[10px]` | только плотная метка и мелкий аватар на фасаде карточки |

- **Насыщенность:** `font-semibold` — заголовки (страница, окно, доска, колонка верхнего уровня, дорожка);
  `font-medium` — кнопки, подписи полей, подколонки, выбранная строка; остальное — обычный.
- `tabular-nums` — номера карточек (`DEV-12`), ключи пространств и счётчики: тот же системный шрифт с ровными цифрами,
  цифры не прыгают (решения PM 26.10). `font-mono` — только коды цвета в полях цвета (метка, тип) и технические поля
  журнала событий.
- **Длинный текст:** однострочные названия (дерево, шапка доски, полоса дорожки, заголовок колонки, списки) —
  `truncate` с многоточием, полное название — в подсказке; название карточки на доске переносится. На доске и панели
  пространства — `TruncatedText` (`shared/components`, LATER-74): обрезанное название получает фокус (Tab) и показывает
  подсказку по наведению и по фокусу; целиком видное — без подсказки и без остановки Tab. Название внутри ссылки или
  кнопки во всю строку (строка дерева, имя файла) — `TruncatedTrigger`: подсказку показывает сама строка, своей остановки
  Tab у названия нет (LATER-109). **Сетка, в которой есть строка с `truncate`** (дерево, «Структура», секции окна
  карточки, плашка блокировки), — `grid-cols-1` (`minmax(0, 1fr)`): у колонки `auto` ширину задаёт самая длинная строка,
  «…» не срабатывает, и панель, страница или окно прокручиваются вбок (LATER-109, U-1 UX-ревью пачки UX-2).
- Регистр — как в предложении; заглавными — только ключ пространства в поле ввода, инициалы в аватаре и заголовок
  компании в дереве (`text-xs uppercase`, когда компаний несколько; длинный — «…» и подсказка, `TruncatedText`).

## 7. Состояния

| Состояние | Как выглядит |
|---|---|
| Наведение | строки, пункты меню, `ghost`/`outline` — фон `accent` и текст `foreground`; основная кнопка — `primary/90`; ссылка — подчёркивание; строка таблицы — `muted/50`; невыбранная вкладка — текст `foreground`; карточка на доске — в светлой `shadow-sm`, в тёмной рамка светлее. Наведение (серое) отличается от выбранного: выбранная строка при наведении остаётся выбранной |
| Фокус с клавиатуры | рамка цвета `ring` (= акцент) — **одно правило `:focus-visible` в base-слое `index.css`**: 2 px с отступом 2 px (решение PM 26.10, шаг 1, п. 5). Между рамкой и элементом — фон, поэтому рамка видна и на главной кнопке, и на любой поверхности обеих тем (4,6–6,5:1). Компоненты своей рамки не задают. Свои рамки: **поля ввода — `ring-2` без отступа** (`Input`, `Textarea`, `NativeSelect`, название в окне карточки; редактор текста и форма новой карточки — `focus-within:ring-2`), у текстового поля рамка видна и от щелчка — так браузер понимает фокус в поле; **пункт меню и строка списка выбора** (`DropdownMenuItem` и его виды, строки выбора карточки и пользователя) — рамка внутри пункта с клавиатуры (`-outline-offset-2`; одна заливка `accent` — 1,09:1 к меню, LATER-115); Radix сам ставит фокус на пункт под указателем, и Chromium считает его `:focus-visible` — поэтому меню, пока подсветку двигает указатель, помечено `data-pointer-focus` и рамка пунктов погашена до первой клавиши (как у вкладок, ниже); в списке с полем поиска (`CommandItem`, выбор человека) фокус остаётся в поле, а рамка внутри пункта отмечает текущий вариант — тот, что выберет Enter, — и видна всегда, в том числе после наведения мышью (cmdk переводит на него текущий вариант); **вкладка в прокручиваемой полосе** (разделы админки) — внутри; выбор дорожки в форме новой карточки — `ring-2 ring-inset` внутри строки. Без рамки — только элемент, который получает фокус не с клавиатуры (окно при открытии, место доски из дерева), — `outline-none`. От щелчка мышью рамки нет (`focus-visible`). **Вкладки — рамка только с клавиатуры** (решение PM 22.10, U-1): одного `focus-visible` не хватает — Radix `Tabs` в `onMouseDown` сам вызывает `focus()`, и Chromium считает такой фокус `:focus-visible` (проверено E2E `focus-ring.spec.ts`), поэтому `TabsTrigger` помечает фокус от указателя `data-pointer-focus` и гасит рамку до первой клавиши. Ловушка Tailwind 4: `outline-hidden` и `outline-none` обнуляют и стиль рамки — своя рамка поверх них — с `outline-solid` |
| Выбранное, активное | **один признак формы — полоска акцента — и подложка `selected`** (заливка к фону меньше 3:1, полоска — 5,8:1): строка дерева и пункт панели «Администрирование» — подложка, полоска 2 px слева (`shadow-[inset_2px_0_0_var(--primary)]`) и `font-medium`; раздел полосы — подложка, значок `selected-foreground`, полоска 3 px у края полосы; вкладка — светлая (`background`) на сером списке и полоса акцента 2 px снизу (`inset-shadow`), в тёмной вместо тени — рамка `input`; вкладка раздела админки («Пользователи», как в Kaiten, LATER-114: ссылки, значок `size-5` над подписью `text-sm font-medium` — у всех, чтобы выбранная не меняла ширину, под списком — `border-b`, рамка фокуса внутри) — подчёркнута `border-b-2 border-primary`, текст `foreground`; `font-medium` у выбранного пункта не должен менять его ширину — соседи не сдвигаются (U-8 UX-ревью П2b-2); пункт-флажок меню — галочка слева; пункт-переключатель (меню пользователя, «Тема») — значок слева, галочка справа цветом акцента |
| Недоступное | `opacity-50`, без реакции на указатель; почему недоступно — в подсказке, если причина неочевидна (пункт «Левее» у доски, которая и так с края, — без подсказки). Для экранного диктора `aria-disabled` — только у действительно недоступного: карточка без права переноса открывается, поэтому она без `aria-disabled` и без инструкции переноса (LATER-76) |
| Появляется по наведению | «+ Карточка» под последней карточкой — `opacity-0` → видна по наведению и фокусу; место под неё занято заранее — соседи не сдвигаются |
| Перенос карточки | на месте броска — пунктирная рамка размера карточки (`outline-dashed`, фон `muted-foreground/10`, содержимое скрыто); ячейка под указателем — фон `muted`; переносимая копия — с наклоном и `shadow-lg`; кнопок «+ Карточка» во время переноса нет; свёрнутая дорожка бросок не принимает |
| Загрузка | текст «Загрузка…» серым (и на месте страницы, пока при первой загрузке приложения грузится её код — `RouteLoading`, HydrateFallback); кнопка отправки — «Сохранение…» и недоступна до ответа; заглушки досок не сдвигают то, что уже на экране: ряды ниже первого экрана скрыты, пока его доски не загрузились; ширина места доски в ряду известна до загрузки (по колонкам, задаёт CSS) — вход на страницу и возврат на вкладку «Доски» без «прыжка»; в ряду первого экрана, пока он грузится, видны только первая доска и доска из дерева — остальные строки ряда стояли бы под заглушками и «прыгали» (U-1 UX-ревью варианта Б) |
| Пусто | серый `text-sm`: почему пусто и что сделать (и кнопка действия, если оно доступно пользователю); общая строка — «Ничего не найдено»; пустая доска — пунктирное поле с подсказкой. Окно карточки: пустая секция (чек-листы, связи, блокировки, файлы, ссылки) не показывается — появляется через «+»; пустое описание — пунктирное поле с подсказкой «Добавьте описание…» |
| Ошибка | поле — красная граница и текст ошибки под ним (ошибки 422 раскладываются в поля); страница — `ErrorState` / `NotFoundState` с кнопкой; итог действия — уведомление (`sonner`, справа сверху) |
| Уведомление | справа сверху, в теме экрана (`Toaster` получает `theme`); текст `text-sm`, контраст не меньше 4,5:1, цвета — палитра раздела 2 (успех emerald 50/200/800, ошибка red 50/200/800) или нейтральный `popover` со значком; поверх окна уведомление нажимается, и щелчок по нему не закрывает окно; подписи области и «×» для экранного диктора — по-русски. Цвета — переменные sonner из токенов в `style` у `Toaster` (стили sonner вне слоёв Tailwind — классы их не перебивают; переменная sonner `--success-border` совпадает по имени с нашим токеном — через синоним `--toast-success-border`, иначе цикл, LATER-111), шрифт — `--font-sans`; `pointer-events-auto` у области — иначе под модальным окном уведомление не нажимается; щелчок по уведомлению не закрывает окно под ним (`keepOpenOnToast` в `DialogContent` и `SheetContent`) (LATER-102, LATER-103) |
| Экран «подождите» на всю страницу | как экран ошибки (`ErrorState`): `role="status"`, заголовок `text-xl font-semibold`, пояснение серым, путь дальше кнопкой `outline`; пример — «Открываем файл…» после входа по ссылке на документ (`OpeningFile`, UI-1b). Короткое ожидание без пояснений — серая строка «Загрузка…» |
| Свёрнуто / развёрнуто | шеврон с `aria-expanded`; после переключения фокус остаётся на шевроне (новый элемент на месте старого получает фокус сам); свёрнутая дорожка — строка с названием и счётчиком во всю ширину доски, щелчок по строке разворачивает; свёрнутая доска — шапка «Название · N карточек», щелчок по шапке разворачивает; секция окна карточки — заголовок-кнопка со стрелкой, состояние запоминается в браузере для всех карточек («Сведения» свёрнуты сразу); доска, перешедшая при этом в другую строку ряда, не уезжает: холст держит её шапку на прежнем месте (у верха холста — насколько можно), шеврон с фокусом — на экране (U-2 UX-ревью варианта Б) |
| Перенос доски | за ⠿ (курсор «рука»): под указателем — копия шапки (`opacity-80`, `shadow-lg`), исходная доска — `opacity-50`, место — линия `bg-primary` 3 px там, где доска на самом деле встанет: вертикальная между досками строки; если рядом с соседкой слева доска не поместится — горизонтальная под строкой соседки, длиной в доску; отдельным рядом — горизонтальная во всю ширину между рядами (ответ PM 21.10); раскладка до отпускания не меняется |
| Блокировка, срочность, срок | на фасаде карточки — красная рамка или фон и значок с текстом для экранного диктора; срок — бейдж со значком по состоянию (`DueBadge`): ждёт — календарь с часами, в срок — с галочкой, просрочено и после срока — с крестиком; нижняя строка фасада (срок, «Срочно», счётчики, аватар) переносится — аватар не выходит за край |
| Смена темы | сразу, без перезагрузки; на время смены переходы выключены (`theme-switching`); меню пользователя остаётся открытым — видно, что выбрано; «Как в системе» следует за системной темой на ходу |

Ни одно состояние не обозначается **только цветом**: рядом значок, текст или изменение формы (рамка, насыщенность).

## 8. Значки и подсказки

- Значки — только lucide. Эмодзи — иконка пространства и папки, которую задаёт администратор.
- **Несколько одинаковых кнопок-значков на экране** («+» в заголовках компаний дерева, «⋯» строк) — в подписи
  и подсказке название объекта: «Добавить в «Компания 2»» (U-3 UX-ревью П2b-2).
- **Значок без текста** (кнопка «⋯», шеврон, «+», значок на фасаде) — `aria-label` и **`Tooltip`** (`shared/ui/tooltip`) на
  элементе, который получает фокус, а не атрибут `title` (CLAUDE.md, фронтенд, правило 8; LATER-57). Подсказка — тем
  же текстом, что `aria-label`; короткая запись — `Hint` (`shared/components/Hint`). Фокус, который вернуло закрытое окно
  или меню «⋯», подсказку не открывает (`restoreFocusQuietly`, `shared/ui/restore-focus`): открытая подсказка забрала бы
  следующий Esc у окна под ней (LATER-94, U-5 UX-ревью UI-1a).
- **Меню «⋯»** — `ActionsMenu` (`shared/components`, LATER-75, LATER-80): подпись и подсказка — «Действия с <чем>
  «Название»»; пункт, который открывает окно, — через `opensDialog` (окно забирает фокус у «⋯», закрытое — возвращает).
  Подсказка — по наведению и по фокусу с клавиатуры; фокус, вернувшийся на «⋯» после щелчка мышью, подсказку не
  открывает (она висела бы, пока фокус не уйдёт).
- Обрезанное название — полный текст в подсказке Tooltip, видной и с клавиатуры (`TruncatedText`, раздел 6).
- Подсказка `Tooltip` — инверсия (`bg-foreground text-background`): в тёмной теме она светлая с тёмным текстом — так и
  задумано (резюме `ux-reviewer` к LATER-89), контраст тот же, что у основного текста.
- Подсказка — не шире `max-w-sm` (384 px), длинный текст переносится, от края окна — не ближе 8 px (`collisionPadding`):
  так по умолчанию в `TooltipContent` (U-3 UX-ревью пачки UX-2).
- **Любое меню у кнопки с подсказкой** (не только `ActionsMenu`: «+» и «⋯» строки дерева — `RowMenu`) возвращает фокус на
  кнопку в `onCloseAutoFocus` через `restoreFocusQuietly`: иначе после Esc открывается подсказка, и следующий Esc
  закрывает её, а не окно или выезжающее меню под ней (U-2 UX-ревью пачки UX-2).
- **Значок с подсказкой внутри строки-ссылки** (дерево: «доступно всем», «пустая» — LATER-88): внутри ссылки или кнопки
  фокусируемое недопустимо, поэтому в строке на месте значка — пустое место той же ширины, а сам значок (с фокусом и
  Tooltip) — поверх строки рядом, как стрелка раскрытия. «+» и «⋯» строки — поверх конца названия на подложке строки;
  «пустая» — левее их места: невидимые кнопки перехватывали бы указатель над ней.
- **Значки файла в «Файлах» окна карточки** (UI-1b): «Скопировать ссылку на «…»» (`Link2`) → «Скачать «…»» → «Удалить
  «…»» — `ghost`, цель `size-6`, значок `size-4`, зазор `gap-0.5`; у превью картинки — «Открыть «…»». Имя файла — ссылка:
  то, что браузер показывает сам (картинка, видео, PDF), открывается в новой вкладке, остальное скачивается (решение PM
  22.10); обрезанное имя — целиком в подсказке у ссылки (`TruncatedTrigger`, пачка UX-2).

## 9. Тексты

- Все строки — через i18n (`locales/ru/*.json`), по-русски, без технических слов (id, API, коды ошибок). Это касается и
  текстов только для экранного диктора: `aria-label`, `aria-roledescription`, объявления при переносе.
- Регистр — как в предложении. Кавычки — «ёлочки», в том числе вокруг названий объектов в `aria-label` и подсказках
  («Действия с колонкой «Backlog»»). Многоточие — один символ «…»: у процессов («Загрузка…»,
  «Сохранение…») и у пунктов меню, которые открывают окно с вводом или выбором («Изменить…», «Переместить в…»,
  «Удалить…»).
- Кнопка называет действие глаголом («Сохранить», «Добавить участника»); в окне подтверждения кнопка повторяет действие
  («Удалить», а не «Да»), заголовок — вопрос или предупреждение с названием объекта.
- Числа с существительными — формами множественного числа i18next («1 карточка», «5 карточек»).
- Даты — относительные («2 дня назад»), точная дата — в подсказке (README Kaiten, раздел 02): шапка окна карточки,
  комментарии. В ленте «Истории» и на плашке блокировки — точные (решение PM 22.10).
- Пустое значение поля: где его можно изменить — действие («Назначить», «Добавить участников», «Задать срок»); при
  просмотре — «—» во всех полях (`EmptyValue`, решение PM 22.10). Срок, метки и «План, ч», пока не заданы, в окне
  карточки не показываются — их добавляют через «+» (LATER-97; план — решение PM 22.10); «Срочно» видно всегда, при
  просмотре — текстом «Да» / «Нет», а не недоступным флажком.
- Кнопки добавления внизу секций окна карточки — с глаголом («Добавить чек-лист», «Добавить ссылку», «Приложить файл»),
  значок — вровень с краем содержимого секции (`-ml-2.5`); подсказка Ctrl+Enter — тем же глаголом, что кнопка
  («отправить» у нового комментария).
- Ошибки — человеческим языком: что не так и что сделать; текст 422 приходит с сервера.
- Копирование ссылки в буфер обмена — `useCopyLink` (`shared/components`; внутри — `copyText`): успех — «Ссылка …
  скопирована»; браузер не дал буфер (страница не на https и не на localhost, запрет) — окно с выделенной ссылкой, чтобы
  скопировать её вручную (`ManualCopyDialog`, U-6 UX-ревью UI-1b), а не «скопирована».

## 10. Раскладка и прокрутка

- Окно браузера не прокручивается; прокручиваются `main` обычной страницы и холст страницы досок, тело доски — вбок
  (ADR-0019, ловушки CLAUDE.md). Шапка доски, заголовки колонок и полоса дорожки закреплены при прокрутке.
- Ширины, на которых проверяем: **1280** (узкое рабочее окно), **1440** (частый ноутбук: доска в 4 колонки — 1138 px —
  при открытом дереве уже шире холста) и **1920** (широкое); страницу пространства — ещё **768** и **1024** с рядом из 3–4
  досок (LATER-81). Меньше 768 px — дерево выезжающей панелью поверх страницы. **768 px и уже —
  доски в колонку**: рядом с деревом холсту остаётся около 450 px. Ряды — с 769 px, брейкпоинт `rows` (`rows:` /
  `max-rows:`), а не `md:` — у Tailwind `md` начинается с 768 включительно.
- Доска — блок на холсте: ширина по колонкам, высота по содержимому, фон холста — справа и снизу (ADR-0019).
- **Доска листается вбок** (шире видимой части): у края тела и строки заголовков колонок, за которым ещё есть колонки, —
  содержимое растворяется в фоне доски: градиент `from-board` к прозрачному, 24 px (`w-6`) — видно в обеих темах (тёмная
  тень `edge-shade` на тёмной доске терялась, U-11 UX-ревью прототипов); докручено до края — растворения нет, у доски уже
  холста — нет вовсе (U-7 UX-ревью варианта Б, дополнение PM 21.10). Полоса прокрутки на macOS скрыта — иначе не видно, что
  доска листается.
- **Заголовок колонки** (как в Kaiten, README Kaiten, раздел 03; LATER-77): название слева на всю оставшуюся ширину;
  справа — точка категории (`size-2` в цели `size-6`, с подсказкой Tooltip «Очередь» / «В работе» / «Готово», в порядке
  Tab; только у колонки верхнего уровня — подколонки наследуют категорию), счётчик карточек (`text-xs tabular-nums`), «+»
  и «⋯». Текстового бейджа категории нет — он съедал ширину названия.
- **Страница пространства:** панель над холстом — всегда одна строка: название, ключ, ⓘ, вкладки «Доски / Участники /
  Метки», сразу за ними «Архив досок» и «Создать доску» (как в Kaiten; только на вкладке «Доски»), справа — «Изменить»;
  правая часть панели — под «Фильтры» (этап 6). **Узкая панель** — по ширине самой панели, а не окна (container query,
  уже 56rem = 896 px; с открытым деревом — окно до ~1210 px): «Название · ключ · ⓘ · вкладки · ⋯», кнопки — пунктами
  меню «⋯» (только доступные; нет ни одного — нет и «⋯»). Название обрезается с подсказкой; на экране уже 480 px ключа
  нет, ⓘ остаётся (решения PM 20.10 и 21.10, LATER-74; мобильная версия целиком — отдельный кандидат). Новая панель
  или полоса с переменным набором кнопок — так же: узкий вид по её ширине (`@container`). Доски рядами, ряды — от левого
  края, доски ряда выровнены по верху. Доска из дерева —
  страница пространства, прокрученная так, что доска у верха холста; над ней — зазор между строками ряда (12 px), а не поле
  холста (16 px): край доски выше не торчит (U-6 UX-ревью варианта Б). Свернуть доску ˄ — последней кнопкой шапки, после «⋯».
- У кнопок блока доски, которых на странице несколько, в подписи — название доски («Действия с доской «Продукт»»,
  «Свернуть доску «Продукт»»).
- **Окно карточки** (UI-1a, README Kaiten, раздел 02): большое окно поверх своей доски или страницы пространства, адрес
  `/cards/KEY-N` (`/spaces/KEY/cards/KEY-N`). Закрытие — на то же место прокрутки: открытое с доски — шагом назад по
  истории, по прямой ссылке — заменой адреса. Сверху вниз: шапка (название правится на месте; «DEV-12 · Заказчик ФИО»;
  «Создана / Перемещена N назад») → ряд действий («+» — как в Kaiten, две колонки: слева системные пункты группами
  «Основное», «Связи», «Остальное», справа «Поля» (до этапа 5 — неактивная заглушка); только разрешённые пункты, нет ни
  одного — нет «+»; «⋯») →
  активная блокировка → «Основные параметры» → «Описание» → чек-листы → связи → блокировки (история) → файлы → ссылки →
  «Сведения» → вкладки «Комментарии» / «История». Файл можно бросить на любое место окна. Новая секция или кнопка ряда
  действий — по этому порядку и README Kaiten.
- **Известное поведение (решение PM 20.10, U-12):** если свернуть последнюю дорожку, когда холст прокручен к её
  середине, холст упирается в конец прокрутки, и полоса дорожки уезжает от указателя вниз. Так и оставлено — не
  находка.

## 11. Доступность и контраст

- **Контраст (WCAG 2.2 AA):** текст — не меньше 4,5:1 (крупный — от 24 px или от 18,66 px полужирным — 3:1); границы и
  заливки, по которым узнают элемент управления и его состояние (фокус, выбранное), — не меньше 3:1 к соседнему цвету.
- **Фокус при открытии окна** — на первом поле ввода; сразу выполняемое или разрушающее действие («Снять», «Удалить»)
  первым фокус не получает (`onOpenAutoFocus`; U-2 UX-ревью П2b-2).
- **Рамка фокуса внутри контейнера с прокруткой** (полоса вкладок, список с `overflow`) — рамка внутри
  (`-outline-offset-2`) или поле контейнера не меньше 4 px (рамка 2 px + отступ 2 px): наружную рамку контейнер срезает
  (U-1 UX-ревью П2b-2; дерево и панель «Администрирование» — `pt-1` и `scroll-py-1`: строка, до которой дошли Tab в
  прокрученном списке, встаёт в 4 px от края, U-14 UX-ревью прототипов).
- **Обе темы:** экран проверяется в светлой и тёмной теме — контраст, светлые пятна, рамка фокуса (E2E-проект `dark`,
  `e2e/dark`; `ux-reviewer` смотрит обе).
- **Клавиатура:** всё, что делается мышью, делается с клавиатуры; порядок Tab — как на экране (удержание фокуса в автотестах
  проверять переходом Tab с соседнего элемента, а не `element.focus()` — иначе ошибки вроде U-4 UX-ревью варианта Б не видно); Esc закрывает окно и
  меню, фокус возвращается на кнопку, которая их открыла (окно из пункта меню — на кнопку меню «⋯», окно карточки — на
  её плитку, и открытое по прямой ссылке тоже, если плитка на доске; `shared/ui/restore-focus`). Встроенная форма
  (новая карточка, блокировка, описание) после Esc, «Отмена» и сохранения возвращает фокус на кнопку, которая её открыла
  (`useReturnFocusOnClose`; кнопка на время формы скрыта, а не убрана), — ушли из формы сами, фокус не трогаем
  (LATER-107, U-9); так же строка с полем, добавленная через «+» («План, ч»): Esc убирает пустую строку, фокус — на «+». Меню на экране уже 768 px — `Sheet`: Esc, фокус внутри, возврат на «Открыть меню» (LATER-108).
  Панель кнопок (форматирование текста) — одна остановка Tab, по кнопкам — стрелки, Home и End (WAI-ARIA toolbar, U-4). **Окно карточки:** при открытии фокус — на самом окне (не в поле названия); Esc
  в поле с текстом выводит из поля (текст остаётся), в названии — отменяет правку; закрытие окна с несохранённым текстом
  (Esc, щелчок мимо, ✕, «Назад») спрашивает «Закрыть без сохранения?» (`useUnsavedText`, решение PM к UI-1a); у панели вкладки (`TabsContent`), внутри которой есть свои элементы с фокусом, —
  без `tabindex`, иначе невидимая остановка Tab; доска, открытая из дерева, получает фокус (место доски `tabIndex=-1`,
  без прокрутки) — следующий Tab ведёт в неё; карточку можно перенести с клавиатуры (пробел, стрелки,
  пробел; Esc — отмена). Элемент тела доски, получивший фокус с клавиатуры, — целиком в видимой части тела по горизонтали:
  тело прокручивается вбок само (Chrome не прокручивает частично видимое) с запасом в ширину затенения края (24 px), холст
  и окно — нет; так же строка заголовков колонок; щелчок мышью и фокус в меню доску не сдвигают (UX-ревью LATER-81, U-3).
- Шевроны сворачивания — `aria-expanded`; переключатели — `aria-pressed`; значки без текста — `aria-label`.
- Цели щелчка — не меньше 24×24 px.
- Видимая подпись кнопки входит в её доступное имя и стоит в начале (WCAG 2.5.3): голосовая команда «нажми Карточка»
  должна найти «+ Карточка».
