# Хотфикс LATER-119 — уязвимость phpunit (GHSA-9vw2-f4vp-x7gf) — журнал работ

Карточка: **LATER-119** («Бэклог», «Взято в работу»). Ветка `hotfix/later-119` от main `353e23e`, рабочая копия
`.claude/worktrees/hotfix-phpunit`. PR [#35](https://github.com/luvu1uvu/selen/pull/35).

## Причина

- 27.10 в 03:15 UTC опубликована уязвимость
  [GHSA-9vw2-f4vp-x7gf](https://github.com/sebastianbergmann/phpunit/security/advisories/GHSA-9vw2-f4vp-x7gf):
  phpunit 13.4.0–13.4.3 — выполнение кода другим локальным пользователем через общую временную папку при покрытии PHPT.
  Это инструмент тестов (dev-зависимость), в production не попадает.
- У нас был phpunit 13.4.1, поэтому проверка «Зависимости» в CI «Security» (`make audit-deps`, ADR-0020) стала красной на
  любом коммите, в том числе в PR #34 (редизайн, шаг 2), — изменения веток тут ни при чём.

## Что сделано

- Исправленный phpunit 13.4.4+ ни одна версия pest пока не поддерживает: pest 5.3.3 требует phpunit `^13.4.3` и запрещает
  более новые. Поэтому откат на последнюю незатронутую связку, выбранную composer (`composer.lock`): phpunit 13.4.1 →
  13.3.6, pest 5.3.1 → 5.3.0, paratest 7.26.1 → 7.25.0, pest-plugin-profanity 5.0.1 → 5.0.0.
- **Запрет уязвимых версий** (решение PM 27.10): в `backend/composer.json` —
  `"conflict": { "phpunit/phpunit": ">=13.4.0 <13.4.4" }`. В JSON комментариев нет — причина записана здесь. Без запрета
  следующее обновление, в том числе Dependabot, вернуло бы 13.4.0–13.4.3 (pest 5.3.1–5.3.3 их и требует). Когда pest
  поддержит phpunit 13.4.4+, обычное обновление поднимет версии само; запрет можно убрать, когда ни одна допустимая
  связка не попадает в 13.4.0–13.4.3.
- Проверка: `composer audit` — без уязвимостей; `composer why-not phpunit/phpunit 13.4.3` — запрещён нашим `conflict`;
  `make lint && make test` зелёные.
