## Задание PM (описание карточки, кратко)

Субагент `ux-reviewer` по образцу `security-auditor` — только смотрит. Зовут в подэтапе и хотфиксе, где меняется
интерфейс: после тестировщика, до отчёта PM (бюджет субагентов +1 для UI-задач). Открывает изменённые экраны на dev
в нескольких состояниях (пусто / мало / много данных, свёрнуто / развёрнуто, окно 1280 и 1920, светлая тема), сверяет
с README Kaiten и правилами вида. Ищет пустоты и отступы, несогласованность, «прыжки» раскладки, обрезанный текст,
слабо заметные состояния, пустые состояния без подсказки, контраст и клавиатуру, подсказки к значкам, непонятные
тексты. Правила вида — новый `docs/ui-guidelines.md`, собранный из текущего интерфейса. Результат — находки «важно /
мелочь / вкус». ADR, CLAUDE.md, пробный прогон по текущей доске.

## План (утверждён PM 20.10) и решения PM

План — в сессии 20.10: агент без Bash и без записи, hook с белым списком (адреса только dev, JS только чтение,
секреты не читаются, проверка hook первым действием), чек-лист из 12 пунктов, уровни, формат отчёта;
`docs/ui-guidelines.md` — из токенов `index.css`, частот классов Tailwind, компонентов `shared/ui`, раскладки досок
(ADR-0019) и текстов `locales/ru`; правила в CLAUDE.md, ADR-0023; пробный прогон — отдельной сессией на этой ветке
(агент из нового описания доступен только новой сессии).

Ответы PM (20.10):
1. Находки «важно» пробного прогона — карточками `make pm-bug` с меткой «UX», не в этом PR.
2. Hook не активен — браузер не открывать, только код и правила вида, об этом — первой строкой отчёта.
3. Самостоятельный мёрж — только PR, где **все** файлы в `docs/stages/` и **нет изображений**. PR с любой картинкой —
   обычный порядок, после «принято» (репозиторий публичный, картинку должен увидеть PM).
4. Браузер: агент работает только в своей новой вкладке (создаёт сам, закрывает в конце), чужие вкладки не переключает
   и не трогает — встроенным браузером одновременно пользуются PM и другие сессии (в том числе со стендом). В
   инструкции и, если возможно, в hook (действия только с `tabId`, созданным агентом).
5. Правило о мёрже — строкой в «Изменения» ADR-0014, не в ADR-0023.

## Проверено до кода (встроенный браузер, 20.10)

- `tabs_create` открывает вкладку в фоне и возвращает `{"tabId": "tab-1", …}`; номера вкладок идут подряд
  (`seed`, `tab-1`…) — угадываемы, поэтому hook запоминает только те, что вернул `tabs_create` агента.
- Фоновая вкладка работает целиком: `navigate`, `resize_window` (1280×800 — только в этой вкладке; у соседней размер
  не меняется), скриншот, JS. Переключать вкладку на передний план агенту не нужно.
- При закрытой панели браузера `tabs_create` не создаёт вкладку («Browser pane isn't open yet»), а `navigate` без
  `tabId` открыл бы панель в общей вкладке. Поэтому: панель открывает основная сессия до вызова агента; `navigate`
  без `tabId` hook запрещает.
- Cookie у вкладок общие и не зависят от порта: вход на `127.0.0.1:8080` делил бы cookie со стендом
  `127.0.0.1:8081`. Агенту разрешён только `http://localhost:8080`.
