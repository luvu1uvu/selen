## Решения PM по плану (21.10)

План подтверждён с поправками:
1. **Несохранённый текст.** Первый Esc выходит из редактирования (текст остаётся); если несохранённый текст остался,
   следующее закрытие спрашивает «Закрыть без сохранения?». Так же — щелчок мимо окна и «Назад». Тест-кейс — ТК-UI1.23.
2. **Пустые секции скрыты**, поэтому файл можно перетащить на любое место окна — он становится вложением. «+» показывает
   только разрешённое: комментатору — только «Файл», тому, кто не может ни править, ни комментировать (например, карточка
   в архиве), «+» не показывается. Тест-кейсы — ТК-UI1.24, ТК-UI1.25.
3. **PDF в UI-1b — вариант А:** открывается в браузере только файл, который сервер сам определил как PDF по содержимому
   (не по имени и не по расширению); `nosniff` остаётся. Проверяет аудитор в UI-1b.
4. Метку «UI-1» на LATER-90 поставил PM; `pm-task` в этом PR не трогаем.
5. Правки существующих тестов — только из-за переезда кнопок, каждая с объяснением в отчёте.

Остальные решения по умолчанию (раздел 13 плана) приняты.

## План UI-1a (подтверждён PM 21.10 с поправками выше)

### 1. Окно

- Новый компонент `CardWindow` вместо `CardPanel` (узкая панель `Sheet` справа) — на `Dialog` shadcn/Radix, модальное.
  Ширина — до `max-w-3xl` (768 px — ближайший к «около 800 px» шаг шкалы, правила вида, раздел 4), у верха экрана с
  отступом, высота — по содержимому, не выше экрана: прокручивается содержимое окна, крестик ✕ в правом верхнем углу
  остаётся на месте.
- **Узкий экран** (уже 640 px, `sm`): окно на весь экран, без скругления.
- **Адреса — прежние:** `/cards/KEY-N` (поверх своей доски) и `/spaces/KEY/cards/KEY-N` (поверх страницы пространства,
  ADR-0019). Прямой адрес открывает доску (пространство) и окно поверх неё.
- **Закрытие:** Esc, щелчок по затемнению, ✕, «Назад» браузера. Доска под окном не перерисовывается и не прокручивается
  (та же страница под другим адресом — как сейчас).
  - Окно, открытое с доски, закрывается **шагом назад по истории** — так же, как «Назад»: доска на том же месте,
    «Вперёд» снова открывает карточку. Сейчас закрытие добавляет в историю новую запись доски, и «Назад» после закрытия
    снова открывает карточку.
  - Окно, открытое по прямой ссылке, при закрытии **заменяет** адрес на доску (пространство) — лишней записи в истории нет.
  - Переход из окна к связанной карточке — новый адрес поверх той же страницы; закрытие возвращает к доске, с которой
    начали, одним действием, «Назад» — к предыдущей карточке.
- **Esc и несохранённый текст (решение PM 1):** открытое меню или всплывающий список Esc закрывает первым. В изменённом
  названии Esc отменяет правку. В поле с текстом (описание, комментарий, причина блокировки, формы добавления) первый Esc
  выходит из редактирования — фокус уходит на окно, текст остаётся. Закрытие окна (Esc, щелчок мимо, ✕, «Назад», переход
  к другой карточке) при несохранённом тексте спрашивает «Закрыть без сохранения?»: кнопка «Закрыть без сохранения» —
  закрыть, «Продолжить редактирование» — остаться. Технически — один путь: закрытие — это переход по адресу, а `useBlocker` React Router
  перехватывает его, пока есть несохранённый текст.
- **Фокус** (как у диалогов shadcn, с одним отличием): фокус заперт в окне, Tab — по порядку на экране; при закрытии фокус
  возвращается на плитку карточки (`restore-focus`, как сейчас). Отличие: при открытии фокус — на самом окне (диктор
  читает название карточки), а не в первом поле: первым полем было бы название, и первая нажатая клавиша правила бы его.
- **Загрузка и ошибки — как сейчас:** окно сразу своего размера, внутри «Загрузка…»; нет карточки или нет доступа — на
  `/cards/…` «Карточка не найдена» на месте доски, на странице пространства — уведомление и возврат к пространству.

### 2. Шапка

- **Название** — крупно (`text-xl font-semibold`), переносится на сколько нужно строк. У того, кто может править, — поле
  без рамки того же вида (рамка — при наведении и фокусе): Enter или уход фокуса — сохранить, Esc — отменить правку,
  пустое не сохраняется. Без права правки — текст. Подпись поля для диктора — «Название» (на ней держатся приёмочные
  ТК-3.36), имя окна — название карточки (ТК-L55.21).
- **Строка под названием** (`text-sm`): номер `DEV-12` моноширинным — щелчок копирует ссылку на карточку (подсказка
  «Скопировать ссылку на карточку», уведомление «Ссылка скопирована») · «Заказчик Анна Смирнова» — у редактора имя —
  кнопка выбора заказчика (список участников пространства с поиском), без права — текст. Номер — наш ключ `DEV-12`, а не
  «#12»: так карточку зовут на доске, в адресе и в связях.
- **Серая строка** (`text-xs text-muted-foreground`): «Создана 3 дня назад · Перемещена 5 часов назад»; точные дата
  и время (и «кем создана») — в подсказке Tooltip по наведению и по фокусу. «Перемещена» — последний переход в другое
  место: колонка, дорожка, доска (включая возврат из архива в другое место). Перестановка внутри ячейки и смена типа
  колонки — не перемещение. Карточку не перемещали — только «Создана».
  **Сервер:** в ответ карточки добавляется поле `moved_at` — из того же запроса к `card_transitions`, что и метрики
  (`CardFlowMetrics`): нового запроса нет, ответ API только расширяется. Pest-тест.
- Карточка в архиве — плашка «Карточка в архиве» под шапкой (как сейчас), правка недоступна.
- **Активная блокировка** — заметная плашка сразу под рядом действий (в Kaiten заблокированную карточку видно сразу):
  причина или блокирующая карточка, кто и когда, кнопка «Снять блокировку». История эпизодов — в секции «Блокировки».

### 3. Ряд действий

Горизонтальная линия во всю ширину окна; на её левом конце — круглая кнопка «+» (основной цвет), на правом — «⋯».
Кнопки этапов 7 и 10 встанут справа, перед «⋯».

- **«+» → меню «Добавить»:** Чек-лист · Файл… · Ссылку… · Родительскую карточку… · Дочернюю карточку… · Блокировку….
  Пункт показывает нужную секцию (пустая секция скрыта — ниже), открывает в ней форму добавления и ставит фокус в её
  первое поле; «Файл…» сразу открывает выбор файла. Пункты — по правам, как сейчас: файл — право комментировать
  (`permissions.comment`), остальное — право правки; карточка в архиве — ничего. Комментатору — только «Файл…»; нет ни
  одного пункта — нет и «+» (решение PM 2). Подсказка и подпись — «Добавить в карточку».
- **Перетаскивание файла (решение PM 2):** файл, перетащенный на любое место окна, становится вложением (то же право, что
  у «Файл…»); пока файл над окном — рамка и подпись «Отпустите, чтобы приложить файл». Без права — окно файл не принимает.
- **«⋯»** (`ActionsMenu`, «Действия с карточкой «Название»»): Переместить… · Архивировать / Вернуть из архива ·
  Скопировать ссылку · разделитель · Удалить… (в корзину, с подтверждением — только системный администратор, как сейчас).

### 4. «Основные параметры» (сворачивается)

Две колонки: название поля серым слева (около 160 px), значение справа; на узком экране — название над значением.
Пустое значение у читателя — «—» или «Не назначен».

| Поле | Значение и правка |
|---|---|
| Расположение | «Доска / Колонка (Дорожка)», подколонка — «Колонка / Подколонка»; рядом бейдж категории (Очередь / В работе / Готово), как сейчас. У редактора — кнопка-лупа «Переместить…» (нынешнее окно переноса) |
| Тип | чип: кружок цвета типа с первой буквой названия и название; у редактора — щелчок открывает список типов (активные + текущий, даже архивный, как сейчас) |
| Ответственный | чип с аватаром и именем, пометки «приглашён», «деактивирован», «не в пространстве» — как сейчас; пусто — «Назначить»; у редактора — выбор с поиском и «Снять» |
| Участники | чипы с аватаром, у редактора у каждого «×»; «Добавить участников» — выбор с поиском (кто уже участник — не в списке) |
| Срок | бейдж срока, как на фасаде (просрочен / сегодня), с датой; у редактора — щелчок открывает поля даты и времени (как сейчас) и «Убрать срок»; пусто — «Не задан» |
| Срочно | флажок |
| Метки | цветные метки; у редактора — «Изменить метки» (нынешнее меню «Общие / Пространства») |
| План, ч | число, шаг 0,5 (поле как сейчас) |
| … | место под пользовательские поля пространства — этап 5 |

Заказчик — в строке под названием (как в Kaiten), отдельной строки нет.

**Выбор человека** (заказчик, ответственный, участники) — всплывающий список участников пространства с поиском по имени
(без деактивированных, как сейчас): `Popover` + `Command` shadcn (`npx shadcn add command`, пакет `cmdk`) — стандартный
путь shadcn для выбора из длинного списка (~100 сотрудников); сейчас — `<select>` на всех.

### 5. «Описание» (сворачивается)

Текст описания. Пустое — серая подсказка «Добавьте описание…»; у редактора щелчок по ней открывает редактор, у читателя —
«Описания нет». Непустое правится кнопкой-карандашом «Изменить описание» в заголовке секции (щелчок по самому тексту не
годится: в нём ссылки и упоминания). Редактор — нынешний (упоминания, вставка картинок).

### 6. Остальные секции — порядок

По образцу Kaiten: сначала то, что описывает работу, затем связи и файлы, служебное — в конце.

1. «Основные параметры» → 2. «Описание» → 3. **«Чек-листы»** → 4. **«Связи»**: родительские, прогресс дочерних (полоса
«Готово дочерних: N из M»), дочерние → 5. **«Блокировки»** — история эпизодов (активная — плашкой вверху) → 6. **«Файлы»** →
7. **«Ссылки»** → 8. **«Сведения»**: кто и когда создал, начата, завершена, время выполнения (lead time), время в работе
(cycle time) → вкладки «Комментарии» / «История».

- Все секции — одного вида: заголовок со стрелкой сворачивания (`aria-expanded`), справа — счётчик (чек-листы, файлы…).
  Свёрнуто или развёрнуто — запоминается в браузере (`usePersistentState`, по виду секции, для всех карточек).
  «Сведения» по умолчанию свёрнута.
- **Пустая секция не показывается** (как в Kaiten): появляется через «+», у читателя пустых секций нет. Исключения —
  «Основные параметры», «Описание» (с подсказкой) и «Сведения».
- Внутри секций — нынешние компоненты без изменения поведения (чек-листы с перетаскиванием и Alt+↑/↓, файлы с превью,
  видео и прогрессом загрузки, выбор карточки для связи и блокировки). Постоянные поля добавления («Новый чек-лист»,
  адрес ссылки) — за кнопкой «+ Добавить …» внизу секции и пунктом «+».

### 7. «Комментарии» и «История»

Внизу окна — вкладки (`Tabs`): «Комментарии» (открыта по умолчанию) и «История». Комментарии — как сейчас: от старых
к новым, правка и удаление своих, упоминания, картинки. История — нынешняя лента (новые сверху); грузится, когда вкладку
открыли.

### 8. Облик

- **Только токены** в новых и переделанных компонентах окна (задел под тёмную тему LATER-89). Цвета палитры в секциях,
  которые попадают в окно, заменяются: плашка блокировки (сейчас `red-*`) — `destructive` с прозрачностью; полоса
  прогресса дочерних (сейчас `emerald-600`) — новый токен `--success` (в `:root` и `@theme inline`). Фасад карточки на
  доске (`CardTile`, `DueBadge`) не трогаем — этап 7 / редизайн.
- Значки без текста — `Tooltip` и `aria-label`; все строки — i18n; относительное время — `Intl.RelativeTimeFormat`
  (новый `formatRelative` в `shared/lib/dates.ts`).
- `docs/ui-guidelines.md` — в том же PR: окно карточки (`max-w-3xl`, на узком — весь экран), секции окна, токен
  `success`, правило про Esc и несохранённый ввод; предложения ux-reviewer.

### 9. Права — без изменений

Окно читает те же флаги ответа карточки, что панель: `edit` (поля, люди, метки, чек-листы, ссылки, связи, блокировки,
перенос — у карточки не в архиве), `comment` (комментарии и файлы), `delete` (корзина), архивировать и вернуть —
`edit` (как сейчас — и у архивной). Видимость — `CardVisibility` на сервере; окно не показывает ничего, чего не
показывала панель. Сервер меняется только полем `moved_at`. Политики, маршруты и матрица доступа не меняются.

### 10. Было → стало

| Было (панель справа) | Стало (окно) |
|---|---|
| Номер и тип над названием | Номер — в строке под названием (щелчок копирует ссылку); тип — «Основные параметры → Тип» |
| Плашка «Карточка в архиве» | Так же, под шапкой |
| Секция «Блокировки» вверху: активные со «Снять», «Заблокировать», история | Активные — плашка под рядом действий со «Снять блокировку»; новая — «+» → «Блокировку…»; история — секция «Блокировки» |
| Поле «Название» | Крупное название в шапке, правка на месте |
| «Где»: доска / колонка / дорожка и категория | «Основные параметры → Расположение» и лупа «Переместить…» |
| Люди: заказчик (список) | Строка под названием «Заказчик ФИО» — выбор по щелчку |
| Люди: ответственный (список) | «Основные параметры → Ответственный» |
| Люди: участники — список, «×», «Добавить участника» | «Основные параметры → Участники»: чипы, «×», «Добавить участников» |
| Метки — «Изменить метки» | «Основные параметры → Метки» |
| Поля: тип, срок (дата, время, «Очистить»), «Срочно», план в часах | «Основные параметры»: Тип, Срок (дата, время, «Убрать срок»), Срочно, План, ч |
| Описание — «Добавить / Изменить описание» | Секция «Описание»: подсказка в пустом, карандаш в заголовке |

## План UI-1b — ссылка на файл, открытая напрямую (LATER-51)

Только план; код — в следующей сессии. Подэтап затрагивает вход и файлы — **точечный аудит безопасности** обязателен.

**Причина.** Файл отдаёт `GET /api/v1/attachments/{id}`. Sanctum считает запрос запросом SPA (и поднимает сессию по
cookie) только при Referer / Origin своего домена (`statefulApi()`); у перехода из адресной строки, новой вкладки или
мессенджера их нет — сессии нет, ответ 401 JSON. Из интерфейса файл открывается, потому что у запроса есть Referer.

**Решение — отдельный веб-маршрут `GET /files/{attachment}`** (`routes/web.php`; сейчас веб-маршрутов нет):
1. **Сессия:** middleware `web` — та же cookie сессии Laravel, что у SPA (Sanctum для SPA и есть web-сессия); `auth`
   (guard `web`), `active` (деактивированный — как вышедший), лимит запросов. `tab-user` не нужен: адрес открывает браузер
   сам, без `X-Selen-User` (как у нынешнего маршрута файла) — строка в `SessionUserMatchTest`.
2. **Права при каждом открытии:** `Gate::authorize('view', $attachment)` — тот же `AttachmentPolicy` → `CardPolicy` →
   `allowCard` → `CardVisibility::canSee`. Нет доступа, карточка в корзине, вложение удалено, нет такого id — одинаковый
   404 без названий файла и карточки. Публичных и вечных ссылок нет.
3. **Отдача:** `AttachmentFiles::response` — X-Accel через nginx (`/_protected/attachments/`, заголовки защиты те же:
   `nosniff`, CSP `sandbox`). Картинки и видео из белого списка — открываются в браузере, остальное — скачивание;
   `?download=1` — всегда скачать (кнопка «Скачать»).
4. **Без входа:** 302 на `/login?next=/files/{id}`. Страница входа после входа: `next` вида `/files/…` — переход браузера
   на этот адрес (это не страница SPA); принимается только относительный путь `/files/<id>` — защита от открытого
   редиректа. Внутренние адреса SPA — как сейчас (`state.from`).
5. **`/api/v1` и CSRF не меняются:** API по-прежнему только для запросов SPA, CSRF не отключается (у GET его и нет).
   Старые ссылки `/api/v1/attachments/{id}`, уже скопированные пользователями, так и отвечают 401 — интерфейс их больше
   не выдаёт.
6. **nginx:** `location ^~ /files/` → php-fpm в `docker/nginx/default.conf` (dev), `prod.conf.example` (стенд и боевой) и
   `docker/e2e/nginx.conf`.
7. **Интерфейс:** `AttachmentResource.url` → `/files/{id}`; картинки в описании и комментариях — `/files/{id}`; у файла
   в секции «Файлы» — пункт «Скопировать ссылку на файл».
8. **Тесты:** Pest — прямой GET без Referer/Origin вошедшим с доступом → файл (X-Accel-заголовок); без входа → редирект
   на вход с `next`; нет доступа / «только свои» / корзина / удалённое вложение → 404 одного вида; деактивированный → как
   без входа; `/api/v1/…` без признаков SPA → 401 как раньше; `next` с чужим адресом игнорируется. Vitest — вход с `next`.
   E2E — ссылка на файл в новой вкладке (вошедший → картинка; вышедший → вход → файл).
9. **Документы:** дополнение к ADR-0010 (вложения) и ADR-0002 (вход): веб-маршрут файлов, почему не `/api/v1`.

**Вопрос PM к UI-1b — PDF.** LATER-51 просит открывать PDF в браузере. Сейчас PDF скачивается: встроенно отдаются только
картинки и видео, у файлов — CSP `sandbox`, а Chrome не показывает PDF в документе с `sandbox` (вместо файла —
«страница заблокирована»). Варианты: **(А)** PDF открывается в браузере — для PDF свой заголовок CSP без `sandbox`
(`default-src 'none'; object-src 'self'` и т. п.), встроенный просмотрщик браузера изолирован от Selen, но это ослабление
защиты для одного типа файлов — проверит точечный аудит; **(Б)** PDF, как сейчас, скачивается, открывается программой
на компьютере. Рекомендую **(А)** с проверкой аудитором; решение — за PM.
