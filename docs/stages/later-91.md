## Решения по ходу работы

- **Меньше токенов — небольшие сдвиги вида** (в плане для PM):
  - `success` — `emerald-600` → `emerald-700`: один цвет и для полос прогресса, и для выполненного чек-листа на фасаде
    (текст `text-xs` должен быть не меньше 4,5:1, у `emerald-600` — 3,67);
  - текст `Alert` `warning` — `amber-900` → `amber-800`, как у `Badge`;
  - затемнение под меню на узком экране — 40 % → 50 %, как под окнами;
  - обводка срочной карточки — `ring-danger-outline/50` (≈ прежний `red-300`) вместо отдельного токена;
  - от `ring` зависят и границы в фокусе (`focus-visible:border-ring` у полей, кнопок, флажков, названия в окне
    карточки) и при наведении на пустое описание (`hover:border-ring`): они тоже темнее, `#a1a1a1` → `#737373`.
- **Форма новой карточки в колонке — на `card`**, а не на `background` (замечание ревьюера): она стоит среди
  карточек, в тёмной теме фон страницы дал бы «дыру». Сейчас оба белые — вид не меняется.
- **Чёрный, а не почти чёрный текст на метках:** с `#0a0a0a` есть узкая полоса цветов средней яркости, где лучший из
  двух вариантов даёт 4,45:1; с `#000` — не ниже 4,58:1 на любом цвете. Выбор — по контрасту, а не по порогу яркости.
  Метки палитры, кроме серой, теперь с чёрным текстом — это и есть решение PM 10 (белый на них был 2,15–3,96).
- **`#a855f7` в палитре выбора не меняем** (предлагал ux-reviewer): с автоматическим (чёрным) текстом — 5,3:1.
- **Проверка цветов — встроенным правилом ESLint**, без своего плагина: CI уже запускает `npm run lint`; ошибка видна и
  в редакторе. `index.css` ESLint не проверяет — это файл токенов.
- **Автотест правила — в `frontend/eslint.config.test.ts`** рядом с конфигом (Vitest находит его сам; в
  `tsconfig.node.json` — для проверки типов).
