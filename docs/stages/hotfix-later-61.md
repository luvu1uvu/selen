# Хотфикс LATER-61: лимит входа обходится заголовком X-Forwarded-For — журнал работ

Карточка: **LATER-61** («Баги приёмки», метка «безопасность»; аудит 2026-10, S-1). Ветка `hotfix/later-61` от main
`5870b9e`. Рабочая копия — `~/dev/selen/.claude/worktrees/hotfix-later-61-948ef9`: основная копия занята веткой
`layout-1` с чужими правками. Тесты шли одноразовым контейнером php на коде ветки.

## Решения PM (2026-10-19)

- Исправление — как в отчёте аудита:
  - доверять только соседнему прокси;
  - X-Forwarded-For собирает nginx;
  - лимит по email без IP;
  - тест «6-я попытка с разными X-Forwarded-For → 429»;
  - в журнале — настоящий IP.
- Развилку на стенде описали PM до реализации. `tailscale serve` и процессы самого Mac mini приходят в nginx с
  одного адреса шлюза Docker. **Выбран вариант A** с условиями:
  1. доверие прокси — только настройкой стенда (`TRUSTED_PROXIES` в `.env.pm.example`, по умолчанию пусто); на dev,
     в E2E и в шаблоне сервера — никому;
  2. тест: присланный клиентом X-Forwarded-For не становится IP даже при доверенном прокси;
  3. ADR и runbook: почему так, компромисс (процессы на самом Mac mini); для боевого сервера (LATER-31) решение
     принимается заново;
  4. `make host-status` по-прежнему предупреждает о порте стенда не на 127.0.0.1.

  Варианты B и C и почему отклонены — ADR-0021.

## Сделано

- **Вопрос 1 аудита, стенд до исправления.** Через адрес Tailscale ушло 6 `POST /api/v1/auth/login`: несуществующий
  email, неверный пароль, каждый раз новый `X-Forwarded-For`. Ответы — 422 ×5, затем 429. `tailscale serve`
  заменяет заголовок. Из песочницы сессии имя `*.ts.net` не резолвится, поэтому запросы шли через
  `curl --resolve` на адрес узла (100.83.120.85).
- **dev:** nginx видит всех клиентов хоста как `172.19.0.1` (access-log), стенд — как `172.18.0.1`.
- **Код:**
  - убран `trustProxies(at: '*')`;
  - добавлен `config/trustedproxy.php` (`TRUSTED_PROXIES`);
  - новый лимит входа — 10 в минуту на email;
  - nginx dev и E2E передаёт `$remote_addr`, стенда и сервера — `$proxy_add_x_forwarded_for`.
- **Тесты.** Три теста в `LoginTest` падали до исправления:
  - 6-я попытка с разными XFF → 429;
  - лимит по email с разных IP;
  - `auth_audit.ip` — не из заголовка.

  `TrustedProxiesTest` проверяет доверенный прокси. Если в тестах подставить доверие всем (`'*'`), 7 из 11 падают.
  Полный backend — 1451 тест, все прошли.
- **nginx — проверка скриптом.** Одноразовые nginx:1.28 и php-fpm, PHP печатает `REMOTE_ADDR` и
  `HTTP_X_FORWARDED_FOR`:
  - main: `XFF=10.9.9.9` — заголовок клиента доходит до PHP;
  - dev и E2E с исправлением: `XFF=<адрес соединения>`;
  - prod: `XFF=10.9.9.9, 100.64.1.2, <адрес соединения>`.

  `nginx -t` — успешно для всех трёх конфигов.
- **`host-status`:** фильтр `open_ports` помечает `*:8081`, `0.0.0.0:…`, `[::]:…` и адрес tailnet. Сейчас все порты
  Colima на 127.0.0.1, «Всё в порядке.».

- **Точечный аудит** (общий субагент с инструкцией `security-auditor`: агент появится со следующей сессии; только
  чтение): критично 0, важно 1, мелочь 1. Обе находки исправлены:
  - **важно.** При пустом `TRUSTED_PROXIES` (`null`) Laravel доверял всем, если `Host` клиента оканчивается на
    `.on-forge.com` или `.on-vapor.com`. Теперь пусто — пустой список; тест падал до исправления;
  - **мелочь.** `make pm-update` при свежем коде не применяет новое значение `.env`. В runbook и ADR — порядок:
    вписать до `make pm-update`, иначе `make pm-down` и `make pm-up`. Шесть попыток → 429 этого не различают:
    различает ТК-L61.1 (в журнале 100.x).
