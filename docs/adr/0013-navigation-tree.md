# ADR-0013. Дерево навигации: папки и пространства, папки не дают доступа

- **Статус:** принят
- **Дата:** 2026-10-14

## Контекст

До этапа 3 сайдбар был плоским списком пространств с досками. Когда пространств десятки (продуктовые команды,
отделы, подрядчики), нужен порядок: «Mobile» с iOS и Android, «Операции» с OPS и маркетингом. Требования PM
(этап 3): папки любой нужной вложенности, их ведёт системный администратор; пространство переносится между
папками без последствий для ключа, номеров карточек, истории и доступов; **пользователь не должен узнать о папке,
в которой нет ничего доступного ему** (название папки — уже информация: «Увольнения 2027»). Позже в дереве
появятся документы (этап 8) — новый тип элемента не должен требовать переделки дерева. Облик и поведение —
по референсу Kaiten (`docs/ui-reference/kaiten/README.md`, раздел 01).

Главный риск — смешать дерево с правами: если папка начнёт давать или ограничивать доступ, появится второй
источник прав в обход `SpaceAccessResolver` (ADR-0012), и сайдбар, доска и политики разойдутся.

## Решение

### Данные — одна таблица узлов

`nav_nodes`: `id` ULID, `parent_id` → `nav_nodes` (null — корень), `type` folder|space (CHECK; позже `document`),
`name` (только у папки), `icon` (эмодзи, у папки и пространства, необязательна), `space_id` (unique, только у
пространства), `position` (`COLLATE "C"`, дробные ключи — ADR-0007), `archived_at` (только у папки — у пространства
свой `spaces.archived_at`), timestamps. CHECK на согласованность типа и полей; индекс `(parent_id, position)`.

Миграция создаёт узел каждому существующему пространству в корне (по названию), `CreateSpaceAction` — узел в конец
корня. Новый тип элемента дерева — новое значение `type` и своя ссылка (`document_id`), без переделки остального.

Иконка — свойство отображения в дереве, поэтому живёт в узле, а не в `spaces`. Валидация — правило
`App\Rules\Emoji`: ровно одна графема, начинается с эмодзи.

### Правила дерева

- Ведёт только системный администратор: создать, переименовать, задать иконку, архивировать/восстановить папку;
  переместить папку или пространство (в папку, в корень, порядок — по соседям `after_id/before_id`).
- Родитель — корень или активная папка. Папку нельзя переместить в саму себя и во вложенную (рекурсивный CTE).
- **Глубина папок — не больше 4** (`NavNode::MAX_FOLDER_DEPTH`; пространство — на 5-м уровне): панель ~256 px
  с отступом 12 px на уровень; глубже — признак неудачной структуры для компании на 100 человек.
- Изменения дерева сериализуются транзакционной advisory-блокировкой (`NavNode::lockTree()`): проверка глубины
  и циклов и запись не разъезжаются при одновременных перемещениях.
- **Архивировать можно только папку без активного содержимого** (решение PM): активные пространства и папки
  внутри — 422 «сначала перенесите содержимое» со списком. Архивные остаются внутри со своим статусом.
  Восстановленная папка, чей родитель в архиве, возвращается в корень; так же — восстановленное пространство,
  чья папка в архиве. При восстановлении папки можно восстановить и архивные пространства, лежащие прямо в ней
  (`restore_spaces`, по умолчанию нет) — тем же `RestoreSpaceAction`, что в админке «Пространства».
- Перемещение меняет только `nav_nodes.parent_id/position`: ключ, номера карточек, история, метрики и доступы
  не трогаются (тест).

### Папки не дают доступа

Доступ по-прежнему даёт только пространство (ADR-0005, ADR-0012). `App\Services\Navigation\NavigationTree::forUser`:

- права — `Space::accessesOf()` (один запрос резолвера), узлы — одним запросом, доски — одним; обрезка в PHP.
  Число запросов не зависит от размера дерева;
- видна только папка, где на любой глубине есть доступное пользователю активное пространство; **названия прочих
  папок не уходят ни в один ответ** (тест ищет строку во всех ответах API, доступных пользователю). Правило одно
  для всех, **включая системного администратора**, и без пометок вроде «нет доступа»: недоступная папка скрыта
  целиком вместе с содержимым. Полная структура со всеми названиями — только в «Структуре» админки;
- каждое доступное активное пространство видно всегда, даже без досок (иначе администратор нового пространства
  не попадёт в него, чтобы создать первую доску); под ним — активные доски.

Значок «доступно всем» (группа «Все сотрудники», ADR-0012): у пространства — у него есть доступ этой группы;
у папки — в ней есть активное пространство и **все** её активные пространства на любой глубине открыты всем —
по всему дереву, а не по видимой пользователю части (иначе значок обещал бы больше, чем есть). Список открытых
всем пространств читает только резолвер (`spacesOpenToEveryone()`).

### API и журнал

| Метод | Путь | Кто |
|---|---|---|
| GET | `/navigation` — дерево пользователя (вложенные узлы) | все |
| GET | `/admin/navigation` — полное дерево с архивом, плоский список в порядке обхода, `meta.max_depth` | системный админ |
| POST | `/admin/folders` `{name, icon?, parent_id?}` | системный админ |
| PATCH | `/admin/nav-nodes/{node}` `{name?, icon?}` (название — только у папки) | системный админ |
| POST | `/admin/folders/{node}/archive` · `/restore` `{restore_spaces?}` | системный админ |
| POST | `/admin/nav-nodes/{node}/move` `{parent_id, after_id?, before_id?}` | системный админ |
| POST | `/admin/spaces` — плюс необязательные `icon` и `parent_id` (папка, в конец) | системный админ |

Ответы изменений дерева — обновлённое полное дерево. У пространства в `GET /navigation` — `can_manage`
(пользователь администрирует его: может создать доску).

События: `folder.created`, `folder.renamed`, `folder.archived`, `folder.restored`,
`nav_node.moved {node_id, space_id?, from_parent_id, to_parent_id}`, `nav_node.icon_changed {node_id, space_id?}`.
Названия папок и значения иконок в журнал не пишутся — только факт и id.

### Интерфейс (референс Kaiten)

- Слева узкая полоса разделов: «Дерево», «Администрирование» (только системному админу). Будущие разделы встают
  туда же; пустых заглушек нет. Повторный клик по открытому разделу сворачивает панель. Выбранный раздел —
  самостоятельное состояние: не зависит от открытой страницы, запоминается для пользователя в браузере
  (по умолчанию — «Дерево»).
- Панель «Дерево»: заголовок, кнопка сворачивания, поиск по дереву **на клиенте** (папки, пространства по названию
  и ключу, доски; без учёта регистра и «ё»; найденное — вместе с раскрытыми родительскими папками), «+» для
  системного админа (папка или пространство). Раскрытые узлы и свёрнутость панели — в `localStorage` (ключ с id
  пользователя, обёрнуто в try/catch: без хранилища работает как обычное состояние). Переход по ссылке на
  пространство, доску или карточку раскрывает путь к ней.
- Админка «Структура» (`/admin/structure`): дерево, меню узла — «Изменить…»/«Иконка…», «Переместить в…» (корень
  или папка; недопустимые — недоступны), «Выше»/«Ниже», «Вложенная папка…», «Архивировать»; архивные папки —
  отдельным блоком с восстановлением; архивные пространства — на своих местах, приглушённо, с пометкой «в архиве».
  **Меню, а не перетаскивание** — как колонки (ADR-0007): надёжно, доступно
  с клавиатуры, просто тестировать. Перетаскивание в дереве — в backlog.

## Последствия

- Права не зависят от дерева: новый источник доступа добавляется в резолвер (ADR-0012), дерево его подхватит.
- Документы (этап 8) и другие элементы встают в дерево новым `type`; правила видимости папок для них — те же
  (папка видна, если внутри есть доступный элемент).
- Поиск по дереву — на клиенте по уже загруженному дереву пользователя: мгновенный и не раскрывает лишнего.
  Если дерево вырастет до тысяч узлов, поиск переедет на сервер (этап 6 — общий поиск).
- Тесты: `Navigation/*Test` (CRUD, глубина, циклы, архив, восстановление, перемещения, видимость, отсутствие имён
  скрытых папок, неизменность ключей/номеров/истории/доступов), `Stage3ScenarioTest` (критерии 6, 7, 9),
  frontend-тесты дерева и «Структуры», E2E `tree.spec.ts`.

## Изменения

### Приёмка этапа 3b (2026-10-14): дерево и «Структура», меню в строках дерева — решения PM

**Контекст.** При ручной приёмке «Структуры» перемещение «не отражалось» в дереве сайдбара. Проверено: кеш
дерева после изменений «Структуры» перечитывается (frontend-тест и E2E с открытым деревом), порядок `GET /navigation`
совпадает с `GET /admin/navigation` после любого перемещения (`NavigationOrderTest`). Причина — **скрытые узлы**:
в дереве администратора нет папок без доступных ему пространств (на демо-данных — «Операции» с MKT и OPS, куда
у admin@selen.test нет роли, и пустые папки). «Выше/Ниже» относительно такой папки и перенос в корень (в конец —
после скрытых папок) не меняют видимый в дереве порядок. Кроме того, из «Структуры» не было видно архивных
пространств в папках, и восстановление папки выглядело как «вернулась пустая папка».

Сначала администратору показали все папки с пометками «пустая» / «нет доступа»; PM отменил это по соображениям
конфиденциальности: даже системный администратор не должен видеть в дереве названия того, к чему у него нет
доступа.

**Решение.**
1. **Дерево (`GET /navigation`) — только доступное, для всех одинаково**, без пометок: папка без доступных
   пользователю пространств скрыта целиком. Полная структура со всеми названиями — только в «Структуре».
   Перемещение относительно скрытых узлов в дереве пользователя не заметно — это ожидаемо. Пустые папки в дереве
   позже будет видеть роль «Владелец» (подэтап 3c, backlog).
2. В «Структуре» архивные пространства видны на своих местах — приглушённо, с пометкой «в архиве», без меню
   (перемещать архивное нельзя); у архивной папки — список архивных пространств внутри.
3. Восстановление папки с архивными пространствами — диалог с галочкой «Восстановить также пространства внутри (N)»
   (по умолчанию выключена). Восстанавливаются пространства прямо в папке — `RestoreSpaceAction` (событие
   `space.restored` в журнале); во вложенных архивных папках — нет (восстановленное оттуда ушло бы в корень).
4. После изменений «Структуры» клиент перечитывает все запросы `['spaces', …]` — дерево и списки пространств.
5. **Кнопки «+» и «⋯» в строках дерева** (как в Kaiten): видны при наведении и фокусе с клавиатуры, только
   пункты по правам, нет пунктов — нет кнопки. «+» на папке (системный администратор) — папка и пространство
   сразу в ней (`POST /admin/spaces` с `parent_id`); «+» на пространстве (его администратор, `can_manage`) — доска.
   «⋯» (системный администратор) — переименовать (папку), иконка, «Переместить в…», «Выше/Ниже», архивировать
   (папку) — тот же код, что в «Структуре» (`useStructureActions`), те же запросы и проверки. На скрытых папках
   кнопок нет — их ведут через «Структуру». Пункт «Документ» появится на этапе 8 «Документы».
6. **Выбранный раздел полосы слева** запоминается для пользователя (`selen.nav.section.<id>`) и не зависит от
   открытой страницы: раньше страница админки при обновлении всегда открывала «Администрирование».

**Последствия.** Администратор ведёт структуру целиком в «Структуре»; дерево — рабочая навигация по доступному.
Тесты: `NavigationOrderTest`, `NavigationTreeTest` (системному администратору — те же правила; пустая папка не
видна в дереве, видна в «Структуре»), `StructureTest` (восстановление с галочкой и без, пространство в папке),
frontend `StructureSync.test`, `TreeNodeActions.test`, `AppLayout.test`, E2E `tree.spec.ts`.

### Удаление навсегда пустой папки и пустого пространства (2026-10-15, LATER-43, решение PM)

**Контекст.** До сих пор в Selen ничего не удалялось: пространства и папки только архивировались. PM попросил
удалять их прямо из дерева, если они больше не нужны, — но только пустыми, чтобы не терять работу.

**Решение.**
- В меню «⋯» строки дерева и в «Структуре» (одни действия — `useStructureActions`): «Архивировать» — теперь и для
  пространства (тот же запрос, что в админке «Пространства»), и «Удалить навсегда…» с подтверждением.
- **Папка** удаляется, только если в ней нет вложенных папок и пространств, в том числе архивных
  (`DeleteFolderAction`). В дереве сайдбара видны только папки с доступными пространствами — там они всегда непустые,
  и пункт неактивен с подсказкой; пустые папки удаляются в «Структуре».
- **Пространство** удаляется, только если в нём нет ни одной карточки, в том числе архивной (`DeleteSpaceAction`).
  Вместе с ним удаляется его пустая структура: доски (и архивные) с колонками и дорожками, участники, доступы групп,
  метки пространства, узел дерева. Иначе — 422 с числом карточек и советом архивировать.
- Удаляет только системный администратор: `DELETE /api/v1/admin/folders/{node}`, `DELETE /api/v1/admin/spaces/{space}`.
- Журнал событий (ADR-0003) не трогается: старые записи о папке или пространстве остаются, новые — `folder.deleted`
  (родитель) и `space.deleted` (id удалённых досок).

**Последствия.** Восстановить удалённое нельзя — поэтому только пустое и только с подтверждением. Карточки по-прежнему
не удаляются никогда: пространство с работой — только в архив.

**Уточнение (2026-10-15, LATER-45).** Карточки теперь можно удалять в корзину (ADR-0015), но физически они остаются.
Поэтому пространство удаляется, только если в нём никогда не было карточек — ни активных, ни архивных, ни в корзине;
иначе — только архив.

### Подэтап 3c (2026-10-15): пустые папки у Владельца, пометка в «Структуре» — решение PM

**Контекст.** Отложенное при приёмке 3b: пустую папку (её только что создали и ещё не наполнили) не видит в дереве
никто, а «Структура» показывает её рядом с видимыми папками — перемещения выглядят непредсказуемо.

**Решение** (ADR-0017).
1. Владельцу `GET /navigation` дополнительно отдаёт **по-настоящему пустые** папки — на любой глубине нет ни одного
   пространства, ни активного, ни архивного (в том числе в архивных папках), — с `empty: true`; в сайдбаре —
   приглушённо, «пустая». Остальным — без изменений (`empty` всегда `false`). Пометок «нет доступа» нет, недоступное
   не показывается никому: пустая папка внутри папки без доступных пространств не видна и Владельцу. Узлы теперь
   грузятся все (и архивные папки — чтобы найти пространства в них); число запросов не меняется.
2. «Удалить навсегда…» в «⋯» у пустой папки Владельца доступно прямо из дерева.
3. «Структура» помечает активные узлы, которых нет в дереве текущего пользователя (нет доступа; пустая папка — для
   не-Владельца), значком «Не видно в вашем дереве». Источник — тот же `GET /navigation`; архивные узлы не помечаются
   (у них «в архиве»).

**Последствия.** Тесты: `NavigationTreeTest` (пустые папки у Владельца, с архивным пространством — не пустая, рядом
с недоступным — скрыта, число запросов), frontend `TreePanel.test`, `StructurePage.test`.

### «Права 2.0», П2b-1 (2026-10-23, ADR-0024): дерево у каждой компании своё

Узел дерева принадлежит компании (`nav_nodes.company_id`; родитель и пространство узла — той же компании, составные
FK): корень у каждой компании свой, «Структура» — `admin/companies/{company}/navigation`, папки ведёт администратор
компании (право компании «структура»). `GET /navigation` строит дерево из узлов компаний пользователя — названия папок
других компаний не приходят ни в одном ответе (`CompanyIsolationTest`); Владельцу — пустые папки всех компаний. Пока
компания одна, дерево и «Структура» — как раньше; заголовки компаний в дереве — П2b-2.

### «Права 2.0», П2b-2 (2026-10-26, ADR-0024): заголовки компаний в дереве

`GET /navigation` отвечает деревьями по компаниям: `data: [{ id, name, items }]` — компании, где пользователю есть что
показать, по дате создания компании. Название — только если таких компаний несколько (решение PM 23.10, вопрос 5):
в сайдбаре сверху каждого дерева — заголовок с названием; у кого компания одна, дерево как раньше, названия нет нигде.
«+» (папка, пространство) — в заголовке компании, структуру которой пользователь ведёт (право компании «структура»);
при одной компании — рядом с поиском, как раньше. «⋯» строк — действия «Структуры» компании своего дерева. Число
запросов не зависит от числа компаний (тест).

### «Права 2.0», П2d-1 (2026-10-29, ADR-0024): папки дают доступ

Выдача на папку действует на всё внутри — вложенные папки и пространства, в том числе созданные позже. Дерево строится
из итоговых прав: папка видна, если на неё есть право (выдача на неё или на папку выше) или внутри есть что-то видимое
пользователю; папки над видимой — путь к ней. Названия остальных папок по-прежнему не попадают ни в один ответ; пустая
папка с правом видна и не-Владельцу (с пометкой «пустая»). Права на все узлы — одним запросом резолвера (рекурсивный CTE
предков), число запросов дерева не зависит от числа папок с выдачами и глубины (тест). Значок «доступно всем» — и через
выдачу «Все сотрудники» на папку выше. Перемещение меняет унаследованный доступ: «Переместить в…» заранее показывает,
кто получит и кто потеряет доступ (`move-impact`, считается перемещением в откатываемой транзакции), и отказывает, если
пространство останется без того, кто лично управляет доступом. «Доступ…» папки и пространства — в «Структуре» и меню «⋯»
дерева, ведёт право компании «управлять доступом»; права «Администратора» на папки ролью — П2d-2 (В11). Удаление пустой
папки снимает выдачи на неё (событиями).
