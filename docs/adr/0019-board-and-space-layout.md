# ADR-0019. Раскладка доски и пространства: модель прокрутки, ряды досок, личное сворачивание

- **Статус:** принят (реализуется пакетом из трёх PR: модель прокрутки — PR 1, дорожки и их сворачивание — PR 2,
  страница пространства с рядами досок — PR 3; журнал — `docs/stages/layout-package.md`)
- **Дата:** 2026-10-19

## Контекст

До пакета прокручивался весь документ: на длинной доске верхняя панель, название доски и заголовки колонок уезжали
вместе с карточками, а горизонтальная полоса прокрутки оказывалась под самой длинной колонкой (LATER-4, LATER-50).
Дорожки выглядели отдельными блоками, каждая доска пространства открывалась своей страницей (LATER-55). В Kaiten
(`docs/ui-reference/kaiten/README.md`, раздел 03) все доски пространства — на одном экране **рядами** (узкая доска
рядом с широкой, ряды друг под другом), у доски — шапка и строка заголовков колонок, дорожки — строки внутри блока.

Требования PM: на странице пространства общая вертикальная прокрутка и у каждой доски своя горизонтальная;
закреплены верхняя панель, шапка доски и заголовки колонок; перетаскивание карточек (с автопрокруткой у краёв
и с клавиатуры) работает как раньше; сворачивание дорожек и досок — личное, хранится на сервере и не меняет ни
прав, ни счётчиков, ни метрик; раскладку досок (ряды и порядок) меняет администратор пространства, она общая.
Модель прокрутки проектируется один раз сразу под страницу с несколькими досками.

## Решение

### Модель прокрутки

| Уровень | Как |
|---|---|
| Окно | Не прокручивается: каркас (`AppLayout`) высотой в окно, `overflow: hidden` |
| Верхняя панель и дерево | Вне прокрутки — всегда на месте |
| Обычная страница | Прокручивается `main` |
| Страница досок (`handle: { canvas: true }` у маршрута) | Каркас отдаёт ей всю высоту без отступов; страница держит свой **холст** с вертикальной прокруткой |
| Доска | Тело доски прокручивается **вбок** (`overflow-x: auto`) |

Внутри блока доски шапка (название, ⓘ, «⋯») — `position: sticky; top: 0` в холсте, строка заголовков колонок —
`sticky` под ней. **Ловушка:** `sticky` привязывается к ближайшему прокручиваемому предку, а элемент
с `overflow-x: auto` по правилам CSS прокручиваем и по вертикали — заголовки внутри тела закрепились бы
относительно тела, а не холста. Поэтому строка заголовков **вне** тела (`overflow: hidden`) и повторяет его
`scrollLeft`; родная полоса тела скрыта, вместо неё — полоса-двойник `sticky; bottom: 0` внизу окна. Всё это —
одна горизонтальная прокрутка (`useSyncedScrollLeft`, в обе стороны); горизонтальное колесо тачпада и Shift+колесо
над заголовками и полосой пробрасываются в тело (вертикальный жест не трогаем — едет холст). Так устроены
заголовки в табличных компонентах (например, AG Grid).

Автопрокрутка dnd-kit прокручивает прокручиваемых предков элемента под указателем: у края доски — тело (вбок),
у верхнего и нижнего края окна — холст. Окно не прокручивается никогда. У холста `scroll-padding-top` на высоту
закреплённых шапок — фокус и прокрутка к элементу не прячут его под ними.

«Назад» и «Вперёд»: `ScrollRestoration` React Router работает только с окном, поэтому `useScrollMemory` запоминает
место прокрутки контейнера по записи истории (`location.key`, `sessionStorage`) и восстанавливает его при переходе
по истории — после загрузки данных; новая страница открывается с начала; та же страница под другим адресом
(карточка поверх доски) прокрутку не трогает.

Описание доски — за значком ⓘ (всплывающее окно), «Архив карточек» — пункт меню «⋯»: закреплённая шапка остаётся
в одну строку и помещается на узкой доске (решение PM 19.10).

### Доска — блок на холсте (поправка PM 19.10 к LATER-50)

Как в Kaiten (`docs/ui-reference/kaiten/README.md`, раздел 03, «Доски на холсте»): у холста свой фон (`--canvas`),
заметно темнее досок; доска — блок со своим фоном, границей и скруглением, шапка доски — внутри блока. Ширина блока —
по колонкам (`w-fit`, `max-w-full`): мало колонок — справа от доски виден фон холста, много — доска во всю ширину
холста и прокручивается вбок внутри блока. Высота — по содержимому (не ниже 15rem), ниже — фон холста; не уже 20rem —
шапка не ломается и при одной колонке. Блок обрезает содержимое по скруглению через `overflow: clip` — в отличие от
`hidden`, это не контейнер прокрутки, и закрепление шапки работает от холста. Первоначальное «доска до низа экрана»
(LATER-4) этим заменено; полоса прокрутки вбок у высокой доски по-прежнему прижата к низу окна.

### Ряды досок пространства (PR 3)

- Каждая доска — свой блок на холсте (см. выше). Ширина доски — по её листовым колонкам (без загрузки карточек);
  в ряду широкая доска сжимается до остатка ряда
  и прокручивается вбок внутри блока, узкая не сжимается; холст по горизонтали не прокручивается. На узком экране
  ряды складываются в колонку.
- Раскладка общая: таблица `board_rows` (пространство, `position` — дробный ключ, ADR-0007) и `boards.row_id`;
  `boards.position` — порядок внутри ряда. Меняет её только администратор пространства (`BoardPolicy::manage`):
  перетаскиванием за ⠿ и пунктами меню («Левее», «Правее», «В ряд выше», «В ряд ниже», «Отдельным рядом»).
- Свёрнутая доска сохраняет свою ширину (соседи по ряду не сдвигаются) и не загружает карточки — только счётчик
  видимых пользователю карточек (`CardVisibility`, ADR-0008).

### Личное сворачивание (PR 2 — дорожки, PR 3 — доски)

- Таблицы `collapsed_lanes (user_id, lane_id)` и `collapsed_boards (user_id, board_id)`: есть строка — свёрнуто.
  Повторный запрос безопасен, гонки «последний перезаписал» нет.
- Это **вид, а не доступ**: читаются только в ответе доски (`collapsed_lane_ids`) и списке досок (`collapsed`);
  выборки карточек, `CardVisibility`, счётчики колонок, поиск и метрики их не касаются. Право — просмотр доски
  (`BoardPolicy::view`; не участник — 404).
- В журнал событий не пишется: это личная настройка вида, не изменение данных (как раскрытые папки дерева).

## Последствия

- Новая страница с досками — маршрут с `handle: { canvas: true }` и свой холст; обычной странице ничего делать не
  нужно. Прокрутку в коде и тестах ищем у контейнера (`[data-board-canvas]`, `main`), а не у окна.
- Блок доски (`BoardBlock`) один для страницы доски и рядов пространства; заголовки колонок и тело должны иметь
  одинаковую ширину содержимого (одинаковые колонки и отступы), иначе заголовки разъедутся с колонками.
- Сравнивать раскладку с Kaiten и проверять перетаскивание — E2E: Vitest/jsdom раскладку не считает.

## Изменения

**2026-10-19, перед PR 2 (ответы PM, журнал пакета, раздел 1а).** Свёрнутая доска в ряду **сжимается до ширины своей
шапки** «Название · N карточек», соседи справа сдвигаются влево (вместо «сохраняет ширину, соседи не сдвигаются»
в разделе «Ряды досок»). Свёрнутая дорожка — строка с названием и счётчиком карточек во всю ширину доски, щелчок по
строке её разворачивает. Колонки доски разделены тонкими вертикальными линиями на всю высоту блока (как в Kaiten),
дорожки — строками с тонкой линией между ними: одна сетка вместо серых ячеек.
