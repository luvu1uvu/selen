# ADR-0006. История перемещений карточек (card_transitions) и определения метрик

- **Статус:** принят
- **Дата:** 2026-10-13

## Контекст

Отчёты руководства (этап 9) строятся на времени выполнения задач. Метрики должны быть честными задним
числом: переименование колонки, смена её типа или перестройка доски не должны менять уже посчитанные
цифры. ADR-0003 заложил принцип — специализированная append-only таблица со снимком категории колонки.
На этапе 1 нужно реализовать её и зафиксировать определения lead time и cycle time.

## Решение

### Категории колонок

Три, как в Kaiten: `queue` (очередь), `in_progress` (в работе), `done` (готово). Тип есть только у колонки
первого уровня, подколонки его наследуют. Время в отдельных колонках (например, Review) считается по
`card_transitions` через `from_column_id`/`to_column_id` — отдельные категории для этого не нужны.

### Таблица `card_transitions` (append-only)

| Поле | Зачем |
|---|---|
| `id` bigint identity | строгий порядок записи (при равном `moved_at`) |
| `card_id`, `space_id` | карточка и её пространство (пространство не меняется — для отчётов без join) |
| `from_board_id` / `to_board_id` | доска до и после (карточку можно перенести на другую доску пространства) |
| `from_column_id` / `to_column_id` | листовая колонка до и после; колонка первого уровня выводится из `board_columns.parent_id` (он неизменяем) |
| `from_lane_id` / `to_lane_id` | дорожка до и после |
| `from_category` / `to_category` | **снимок** типа колонки первого уровня на момент перехода |
| `moved_at` timestamptz(6), UTC | время перехода (задаёт приложение) |
| `actor_id` | кто переместил; null — система |
| `reason` | `created`, `manual`, `column_type_changed`, `column_split` |

`from_*` = null только у перехода `created` (CHECK в БД). Таблица защищена как `event_log`: модель
бросает исключение на update/delete, триггер `card_transitions_append_only` запрещает UPDATE, DELETE и
TRUNCATE (общая функция `forbid_append_only_modification()` пишет имя таблицы в сообщение).

### Что считается переходом

| Событие | Переход | reason |
|---|---|---|
| Создание карточки | да, from = null | `created` |
| Перемещение в другую колонку, дорожку или доску | да | `manual` |
| Перестановка внутри той же ячейки | **нет** — меняется только `position` (в журнале `card.reordered`) | — |
| Смена типа колонки, где лежит карточка | да: место прежнее, категория новая | `column_type_changed` |
| Первая подколонка у колонки с карточками | да: карточки переезжают в подколонку, категория та же | `column_split` |
| Восстановление из архива в другую ячейку (если прежняя колонка/дорожка в архиве) | да | `manual` |
| Архивация и восстановление в ту же ячейку | нет (положение не меняется) | — |

### Единая точка записи

`App\Services\Cards\CardPlacement` — единственный код, который меняет положение карточки. В той же
транзакции он: вычисляет позицию, пишет переход, пересчитывает денормализованные поля карточки и пишет
событие `card.moved` в `event_log` (общая лента истории; payload — только id и категории).

### Определения (как реализованы)

- **created_at** — момент перехода `created` (совпадает с `cards.created_at`, микросекунды).
- **first_started_at** — `moved_at` первого перехода с `to_category ∈ {in_progress, done}`: первый вход
  в работу или сразу в «готово», если «в работе» пропущена. После установки не меняется.
- **completed_at** — `moved_at` последнего входа в `done` (переход с `from_category ≠ done` и
  `to_category = done`), если карточка сейчас в `done`. Выход из `done` обнуляет значение, повторное
  завершение даёт новое. Перемещение между колонками «готово» не сдвигает момент завершения.
- **Lead time** = `completed_at − created_at`.
- **Cycle time** = `completed_at − first_started_at`.
- У незавершённой карточки обе метрики не определены (null).

`cards.first_started_at` и `cards.completed_at` — денормализация для быстрых выборок; источник истины —
переходы. Сервис `App\Services\Metrics\CardFlowMetrics::forCard()` считает всё **только по
`card_transitions`**; тесты сверяют его результат с денормализованными полями во всех сценариях (обычный
путь, возврат из «Готово», смена типа колонки, пропуск «в работе», создание сразу в «готово»).

### Почему история не «плывёт»

В переходах хранятся id и снимок категории. Переименование колонки меняет только подпись при показе.
Смена типа колонки пишет **новые** переходы для карточек, которые сейчас в ней лежат, и не трогает старые:
карточка, прошедшая через «Code Review» в понедельник, остаётся прошедшей через `in_progress`, даже если
в среду эту колонку сделали `done`.

## Последствия

- Отчёты этапа 9 строятся SQL-запросами по `card_transitions` (индексы `(card_id, moved_at, id)`,
  `(space_id, moved_at)`, `(to_column_id, moved_at)`, `(from_column_id, moved_at)`).
- Если доска без колонки типа «готово» — метрики по ней не посчитаются; интерфейс предупреждает
  (флаг `has_done_column`).
- Исправить ошибочный переход нельзя — только новым переходом. Это намеренно, как и в `event_log`.
- *2026-10-15, LATER-45 (ADR-0015):* гарантия append-only **не менялась** — триггер в исходном виде. Карточки
  удаляются только в корзину; их переходы остаются в базе, но глобальный scope `CardTransition::OF_LIVE_CARDS`
  по умолчанию исключает их из метрик и отчётов.
