# ADR-0022. Публичный репозиторий с чистой историей; старый — архив selen-archive

- **Статус:** принят
- **Дата:** 2026-10-19
- **Карточки:** LATER-67

## Контекст

- Репозиторий был приватным. CI (backend, frontend, E2E, «Security») идёт на каждый push и PR, а бесплатных минут
  GitHub Actions у приватного репозитория мало. Для публичных репозиториев стандартные раннеры GitHub бесплатны.
- В истории приватного репозитория есть то, что нельзя публиковать:
  - скриншоты Kaiten компании (`docs/ui-reference/kaiten/*.png`, в ветке `layout-1` — ещё два `*.jpg`): реальные
    доски, ФИО сотрудников, ссылка на аккаунт Kaiten компании;
  - названия досок, колонок, полей и кнопок автоматизации компании в тексте README референсов и журналов;
  - адрес стенда в tailnet PM и личный email автора коммитов.
- Удаление последним коммитом из истории ничего не убирает. Переписать историю (`git filter-repo`) и потом доказать,
  что ни в одном из 215 коммитов main и в ветках не осталось ничего лишнего, дороже и рискованнее, чем начать
  историю заново с проверенного дерева.
- Кода, который нельзя показывать, в репозитории нет: секреты — только в `.env` (CLAUDE.md, правило 9), история
  проверяется gitleaks в CI (ADR-0020).

## Решение

Решение PM 2026-10-19.

1. **Архив.** Старый `luvu1uvu/selen` переименован в `luvu1uvu/selen-archive` и остаётся приватным. В нём — вся
   история до переезда, PR #1–#29 с обсуждениями и ревью. Ничего не удаляем.
2. **Новый публичный `luvu1uvu/selen`.** История начинается с одного коммита. Его дерево — `main` архива на момент
   переезда (`dd58889`) без исключённого ниже, с правками переезда: описание референсов словами, правило
   в CLAUDE.md, этот ADR, пометки архива в документах.
3. **Исключено из публичного дерева:**
   - скриншоты Kaiten `docs/ui-reference/kaiten/01-tree.png`, `02-card.png`, `03-space-boards.png`,
     `04-automation-buttons.png`, из ветки `layout-1` — `03-boards-on-canvas-1.jpg`, `-2.jpg`. Вместо них —
     описание раскладки и поведения в `docs/ui-reference/kaiten/README.md`. На `04-automation-buttons.png` ФИО нет,
     но есть названия кнопок автоматизации и колонки компании — он тоже заменён описанием;
   - названия досок, колонок, полей, меток и кнопок компании в тексте — заменены нейтральными;
   - адрес стенда в tailnet (имя хоста и tailnet) в runbook и журнале — заменён шаблоном
     `<имя Mac mini>.<tailnet>.ts.net`; путь с именем пользователя в примере восстановления — шаблоном;
   - личный email автора коммитов. Коммиты — от GitHub noreply-адреса `<id>+luvu1uvu@users.noreply.github.com`
     (локальная настройка git `user.email` основной копии; рабочие копии её наследуют).
4. **Проверка перед публикацией:** gitleaks по дереву; поиск ФИО, email (кроме `*.test`, `*.local`, noreply и
   авторов пакетов в lock-файлах), `kaiten.ru`, внутренних названий компании; каждую картинку смотрели глазами.
   Список найденного — PM, публикация — после «ок».
5. **Правило на будущее** — CLAUDE.md, «Процесс»: реальные данные компании (ФИО, содержимое досок Kaiten,
   внутренние ссылки) в репозиторий не попадают; каждая картинка проверяется перед коммитом.
6. **Ссылки на старые PR.** Номера PR в документах до переезда (#1–#29) — из архива: в начале таких документов
   пометка «архив: selen-archive», прямые ссылки ведут на `github.com/luvu1uvu/selen-archive/pull/N`. Новые PR
   нумеруются в новом репозитории заново с #1. Ссылки в тестах (`…/selen/pull/13` и т. п.) — просто данные, их
   не меняем.
7. **Рабочие копии.** Основная `~/dev/selen` и стенд `~/dev/selen-pm` переведены на новую историю: `origin` — новый
   репозиторий, `archive` — `selen-archive` (для `git log archive/main -- <файл>`). Данные стенда и бэкапы не
   тронуты. Рабочие копии сессий в `.claude/worktrees` на старой истории убраны. Незавершённая ветка `layout-1`
   (PR #29 архива) перенесена новым PR без скриншотов Kaiten; #29 закрыт со ссылкой на новый PR.

## Последствия

- CI в публичном репозитории бесплатный. Dependabot alerts и security updates включаются в настройках нового
  репозитория заново (Settings → Advanced Security), там же — push protection (для публичных репозиториев
  бесплатна); `.github/dependabot.yml` переехал вместе с кодом.
- Код, документация, тест-кейсы и описания PR видны всем. Секреты по-прежнему только в `.env`, gitleaks — на каждом
  push. Отчёт аудита безопасности (`docs/security/`) и runbook (устройство Mac mini — без адресов и секретов)
  остаются в публичном дереве (решение PM 2026-10-19): находки «важно» исправлены, открытые «мелочи» не дают доступа
  извне — стенд только в tailnet. «Мелочи» закрываются до пилота, перед пилотом — полный аудит (`docs/backlog.md`,
  «Эксплуатация»).
- Опубликованное не отозвать (форки, кеши, архивы), поэтому проверка — до коммита, а не после (правило в CLAUDE.md).
- История до переезда, `git blame` и обсуждения PR — только в архиве: `git fetch archive`,
  `git log archive/main -- <файл>`. Доступ к архиву — у тех, кому PM его дал.
- Ссылки `github.com/luvu1uvu/selen/pull/N` вне репозитория (комментарии QA-бота в карточках LATER на стенде) теперь
  ведут в новый репозиторий — на другой PR или в 404. Читать их как ссылки на `selen-archive`.
