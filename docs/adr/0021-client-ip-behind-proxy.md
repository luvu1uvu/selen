# ADR-0021. IP клиента за прокси: кому верить в X-Forwarded-For

- **Статус:** принят
- **Дата:** 2026-10-19
- **Карточки:** LATER-61 (аудит безопасности 2026-10, находка S-1)

## Контекст

- Laravel доверял всем прокси (`trustProxies(at: '*')`), а nginx передавал в PHP заголовок клиента
  (`include fastcgi_params`). Клиентским IP становился самый левый адрес `X-Forwarded-For` — его присылает сам
  клиент. Из-за этого обходились:
  - лимиты входа (email + IP, IP), сброса пароля и страницы приглашения — каждая попытка с новым адресом в заголовке;
  - IP в `auth_audit` подделывался.

  На dev 7 попыток входа с разными `X-Forwarded-For` давали 422, с одинаковым — 429 на шестой.
- В Docker на macOS (Colima) nginx видит любого клиента хоста как шлюз сети Docker: dev — `172.19.0.1`, стенд —
  `172.18.0.1`. На стенде с этого адреса приходят:
  - `tailscale serve` — только он знает настоящий IP пользователя tailnet;
  - любой процесс самого Mac mini: браузер на `127.0.0.1:8081`, curl, сессии Claude, контейнеры Colima.

  nginx не может отличить одних от других.
- **Проверено на стенде 2026-10-19** (вопрос 1 аудита): через адрес Tailscale ушло 6 попыток входа, каждая с новым
  `X-Forwarded-For`. Ответы — 422 ×5, затем 429. `tailscale serve` не передаёт присланный заголовок, а ставит свой:
  адрес устройства в tailnet (так и в исходниках Tailscale, `addProxyForwardedHeaders`).
- Требования PM:
  - клиент не подменяет IP;
  - лимит по IP не склеивает всех пользователей в адрес шлюза — иначе 20 попыток входа в минуту на всех;
  - в журнале — настоящий IP там, где он известен.

## Решение

Вариант A (решение PM 2026-10-19): доверять только прокси на хосте и только там, где он действительно стоит перед
nginx.

### Приложение

- Доверенные прокси задаёт только `TRUSTED_PROXIES`: адреса или подсети через запятую (`config/trustedproxy.php`,
  ключ `trustedproxy.proxies` штатно читает middleware `TrustProxies` Laravel). Без `'*'`.
  - **Пусто — никому** (по умолчанию: dev, E2E, тесты, шаблон будущего сервера). `X-Forwarded-*` не читаются, IP —
    адрес соединения, который видит nginx.
  - Пустая переменная — **пустой список, а не `null`**. При `null` `TrustProxies` сам доверяет всем, если `Host`
    оканчивается на `.on-forge.com` или `.on-vapor.com`, а `Host` присылает клиент. Нашёл точечный аудит, закреплено
    тестом.
  - Если адрес соединения доверенный, IP — крайний правый адрес цепочки не из доверенных подсетей (Symfony). Всё,
    что клиент прислал левее адреса от прокси, не учитывается, даже если прокси когда-нибудь начнёт дописывать к
    заголовку, а не заменять его. Закреплено тестом `tests/Feature/Auth/TrustedProxiesTest.php`.
  - Те же адреса — источник `X-Forwarded-Proto`: через Tailscale (https) у cookie по-прежнему флаг Secure (ADR-0018).
- Лимит входа по email без IP — 10 попыток в минуту на учётную запись с любых адресов. Остаются и прежние лимиты:
  5 в минуту на пару email + IP и 20 в минуту на IP. Перебор пароля одной учётной записи не ускоряется сменой IP.
- Новое место, где нужен IP клиента, — только `$request->ip()`.

### nginx (X-Forwarded-For собирает nginx)

- dev и E2E (`docker/nginx/default.conf`, `docker/e2e/nginx.conf`). Перед ними прокси нет, поэтому
  `fastcgi_param HTTP_X_FORWARDED_FOR $remote_addr`: заголовок клиента до PHP не доходит вовсе.
- Стенд и шаблон будущего сервера (`docker/nginx/prod.conf.example`):
  `fastcgi_param HTTP_X_FORWARDED_FOR $proxy_add_x_forwarded_for` — цепочка плюс адрес соединения. Читается
  Laravel, только если `TRUSTED_PROXIES` задан.

### Стенд

- В `.env.pm.example` — `TRUSTED_PROXIES=` (пусто). `make pm-up` и `make pm-update` дописывают переменную в `.env`
  стенда.
- Значение применяется только при создании контейнеров и кеша конфигурации. `make pm-update` при свежем коде выходит
  сразу и контейнеры не пересоздаёт. Поэтому значение вписывают до `make pm-update`, а если стенд уже обновлён —
  `make pm-down`, затем `make pm-up`.
- На Mac mini за `tailscale serve` PM вписывает `TRUSTED_PROXIES=172.16.0.0/12` (runbook, раздел 13). Это пулы
  сетей Docker: так nginx видит хост. Адреса tailnet (`100.64.0.0/10`) в эту подсеть не входят.
- Итог: вход через Tailscale — с адресом устройства в tailnet (100.x), у каждого устройства свой лимит по IP;
  вход с самого Mac mini — с адресом шлюза `172.18.0.1`, как раньше.

### Рассмотренные варианты

- **B. Не доверять никому нигде.** У всех пользователей стенда один IP — шлюз: общий лимит 20 попыток в минуту, и при
  пилоте через Tailscale вход встанет. В журнале — шлюз вместо адреса из tailnet, через Tailscale пропадает флаг
  Secure. Отклонён.
- **C. Как A, но у Tailscale свой порт** (`tailscale serve` → `127.0.0.1:8082`, доверие — только там). Прямой
  `127.0.0.1:8081` с Mac mini тоже перестаёт подставлять IP. Но процесс на Mac mini может пойти и на `:8082`, так что
  выигрыш — только против своих же процессов. Цена — второй `listen`, порт в compose, перенастройка
  `tailscale serve`, правки runbook и `host-status`. Отклонён.
- **`real_ip` в nginx** (`set_real_ip_from` + `real_ip_header`). Доверие то же, но адрес шлюза пришлось бы вписывать в
  общий конфиг стенда и сервера. А `X-Forwarded-Proto` Laravel всё равно нужно получать от доверенного прокси.
  Отклонён: одно место доверия — `TRUSTED_PROXIES`.

## Последствия

- **Компромисс варианта A.** Процесс на самом Mac mini может подставить любой IP, если обращается к `127.0.0.1:8081`
  напрямую с `X-Forwarded-For`. Это относится к браузеру и curl PM, сессиям Claude и контейнерам Colima, в том числе
  контейнерам самого стенда (172.18.0.x). Это владелец машины и его инструменты: у них и так полный доступ к Docker и
  базе стенда. Сузить список до одного шлюза `172.18.0.1` можно, но тогда при смене подсети сети стенда у всех
  незаметно станет общий IP. Оставлена подсеть. Перебор пароля и для них ограничен
  лимитом по email.
- **Вариант A держится на том, что порты стенда — только на `127.0.0.1`** (ADR-0018). Порт, открытый в сеть, пришёл
  бы через тот же шлюз Docker и получил бы доверие: любой в офисной сети или tailnet снова подменил бы IP.
  `make host-status` и ежечасное задание предупреждают о любом порте, который Colima пробрасывает не на `127.0.0.1`
  (`open_ports` в `scripts/host.sh`). Эту проверку не ослаблять.
- Если сеть стенда получит шлюз вне `172.16.0.0/12`, заголовок перестанет учитываться. Подмены не будет, но у всех
  станет адрес шлюза. Docker выдаёт `192.168.x.0/20`, когда заняты `172.17–31`. Проверка:
  `docker network inspect selen-pm_default`.
- **Боевой сервер (LATER-31) — решение принимается заново**, по его схеме сети:
  - nginx на краю — `TRUSTED_PROXIES` пустой, в nginx — `$remote_addr`;
  - перед nginx TLS-терминатор или балансировщик — только его адрес;
  - подсеть офиса в `TRUSTED_PROXIES` не вписывать: любой сотрудник снова сможет подменить IP.

  Шаблон сервера (`prod.conf.example`, `.env.example`) по умолчанию не доверяет никому.
- Лимит по email позволяет помешать входу коллеги: 10 неверных попыток в минуту блокируют вход в его учётную запись
  на минуту. Принимаем: так устроен любой лимит на учётную запись, попытки видны в журнале с IP.
- `phpunit.xml` задаёт `TRUSTED_PROXIES` пустым: тесты не зависят от `.env` dev.
