# Аудит возможностей Kaiten и сравнение с Selen

Исследование по заданию PM 27.10 ([журнал](../stages/kaiten-audit.md)). Цель — каталог всех функций Kaiten и статус
каждой в Selen, чтобы при переезде ничего не потерять. Код не менялся; карточки на стенде и правки дорожной карты и README
Kaiten — только после решения PM по каталогу.

**Источники.** Пробный пустой аккаунт Kaiten (все функции тарифа открыты до ~9 ноября) — интерфейс целиком: меню, настройки,
разделы администрирования; публичная справка и документация API Kaiten; документы Selen (дорожная карта, README Kaiten,
журналы этапов, ADR) и код (`main` `34a5b62`); поведение сделанного — на dev с демо-данными. Скриншоты Kaiten — только
в приватном архиве (`luvu1uvu/selen-archive`, папка `kaiten-audit/`); здесь — ссылки вида «скрин: kaiten-audit/…».

**Статусы Selen:** ✅ есть · 🟡 частично · 📋 по плану (этап) · 💡 идея без решения (бэклог) · ❌ нет (нигде не упоминается)
· ⛔ не делаем (решение PM).

**Оценки для «нет», «идея» и «частично»:** ценность для нас (внутренний инструмент, ~100 сотрудников) — В высокая / С
средняя / Н низкая; сложность — S (дни) / M (1–2 недели) / L (этап) / XL (несколько этапов); «Куда» — предложение, в какой
этап поставить («—» — не брать).

**Расхождения поведения (есть / частично):**
- UX: в Kaiten пространство и папка переименовываются щелчком по названию в шапке; у нас — только через меню.
- UX: у Kaiten «+ Добавить» в шапке создаёт карточку из любого места (с выбором доски и типа); у нас карточку можно создать только на доске.
- UX: поиск по дереву у нас ищет только по уже загруженным узлам (LATER-30) — для пилота на ~100 человек достаточно, пока дерево целиком грузится сразу.
