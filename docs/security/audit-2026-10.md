### S-1. Лимиты входа обходятся подменой X-Forwarded-For
- **Уровень:** важно.
- **Статус:** исправлено в LATER-61 (ADR-0021): доверенные прокси — только `TRUSTED_PROXIES`, X-Forwarded-For
  собирает nginx, лимит входа по email без IP.
- **Где:**
  - `backend/bootstrap/app.php:31` — `trustProxies(at: '*')`;
  - `vendor/laravel/framework/src/Illuminate/Http/Middleware/TrustProxies.php:83-84,120-123` — `'*'` превращается в
    доверие `0.0.0.0/0` и `::/0`;
  - `vendor/symfony/http-foundation/Request.php:2212-2242` — если доверены все адреса цепочки, клиентским IP считается
    первый (левый) адрес `X-Forwarded-For`, то есть присланный клиентом;
  - `docker/nginx/prod.conf.example:19,28`, `docker/nginx/default.conf:26,35`, `docker/e2e/nginx.conf` —
    `include fastcgi_params` передаёт заголовок клиента как `HTTP_X_FORWARDED_FOR`;
  - `backend/app/Providers/AppServiceProvider.php:87-92` (вход: оба ключа содержат `$request->ip()`), `:99` (сброс
    пароля), `:108-110` (приглашения);
  - `backend/app/Services/EventLog/EventRecorder.php:68` — тот же IP пишется в `auth_audit`.
- **Как воспроизвести:** dev, `POST http://127.0.0.1:8080/api/v1/auth/login` с неверным паролем, `Accept: application/json`,
  каждый раз новый `X-Forwarded-For: 10.0.0.N`.
  - **Подтверждено основной сессией 2026-10-19** (email, которого нет в базе):
    - 7 попыток с разными `X-Forwarded-For` — все 422;
    - 7 попыток с одинаковым — 422 ×5, затем 429.
  - Pest-вариант: 6 попыток с разными `X-Forwarded-For` — на шестой ожидается 429.
- **Почему это проблема:**
  - перебор пароля любой учётной записи, включая Владельца, ограничен только пропускной способностью сервера;
  - ключ «email + IP» тоже обходится;
  - IP в журнале входа подделывается;
  - на будущем сервере так может сделать любой сотрудник. На стенде — с самого Mac mini; через Tailscale — зависит от
    того, дописывает `tailscale serve` свой адрес к присланному заголовку или заменяет его (вопрос 1).
- **Предложение исправления:**
  1. Доверять только непосредственному соседу: `trustProxies(at: ['REMOTE_ADDR'])` или подсети Docker. Тогда клиентом
     станет правый, недоверенный адрес цепочки.
  2. В nginx на краю — `fastcgi_param HTTP_X_FORWARDED_FOR $proxy_add_x_forwarded_for;`, либо `$remote_addr`, если
     перед ним никого нет.
  3. Добавить лимит на email без IP, например `Limit::perMinute(10)->by('email:'.$email)`.

  Тесты: шестая попытка с разными `X-Forwarded-For` → 429; в `auth_audit.ip` — не значение из заголовка.

### S-2. (PR) Hook аудитора пропускал чтение секретов — исправлено в этом PR
- **Уровень:** важно (код этого PR). Исправлено до открытия PR вместе с находками ревью; карточки нет.
- **Было:**
  - Grep со строками по `~/.config` выводил `selen/offsite.env` и `selen/restic-password`;
  - Read по `~/dev/selen-pm/.ENV` проходил: на APFS регистр не различается;
  - Grep по `~/dev` проходил в снапшоты вложений бэкапов.

  Ревью нашло ещё:
  - выполнение программы через `git grep "-O…"` (параметр в кавычках);
  - чтение файлов через неявный `--no-index` (`git diff /dev/null <файл>`);
  - чтение файлов через `git blame -S` и `--ignore-revs-file`.
- **Стало:**
  - символы команды — только `[A-Za-z0-9 ._/:@^~=,%+-]`;
  - пути git — только внутри копии;
  - Read и Grep — только в копиях Selen, на стенде, в агентах launchd и логах Selen;
  - пути приводятся к реальным, регистр не учитывается;

  - сбой hook — запрет.

  Тест `scripts/test-auditor-hook.sh` (72 кейса, в том числе все обходы выше) входит в `make lint` и CI.

### S-3. Перебор email по времени ответа входа
- **Уровень:** мелочь.
- **Где:** `backend/app/Actions/Auth/LoginAction.php:25-29`. Для несуществующего email и для приглашённого без пароля
  `Hash::check` не вызывается.
- **Как воспроизвести:** сравнить время ответа 422 для существующего активного email и для несуществующего. Разница —
  порядка стоимости bcrypt (rounds = 12).
- **Почему это проблема:** можно выяснить, какие адреса заведены. Объём ограничен лимитом входа (но см. S-1).
- **Предложение исправления:** при `$user === null || ! hasActivated()` вызывать `Hash::check($password,
  <фиктивный хеш>)`. Тест — поведенческий: `Hash::check` вызывается.

### S-4. Нет заголовков безопасности в nginx стенда и будущего сервера
- **Уровень:** мелочь.
- **Где:** `docker/nginx/prod.conf.example:6-55` (его монтирует стенд: `docker-compose.pm.yml:37`). Заголовки есть только
  у internal-location вложений.
- **Как воспроизвести:** `curl -sI http://127.0.0.1:8081/`. Нет `Content-Security-Policy`/`frame-ancestors`,
  `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`; в `Server` — версия nginx.
- **Почему это проблема:** SPA можно встроить во фрейм (clickjacking), если жертва внутри tailnet или сети компании.
- **Предложение исправления:** на уровне `server` добавить:
  - `server_tokens off`;
  - `add_header X-Frame-Options DENY always` (или CSP `frame-ancestors 'none'`);
  - `X-Content-Type-Options nosniff`;
  - `Referrer-Policy same-origin`;
  - базовую CSP для SPA (`default-src 'self'`, проверить со сборкой Vite).

  HSTS — там, где завершается TLS. Проверка — E2E: заголовки в ответе `/`.

### S-5. Логи контейнеров: ПДн и токены без срока хранения
- **Уровень:** мелочь.
- **Где:**
  - `docker-compose.pm.yml:30-47` — у сервисов нет `logging` (`max-size`/`max-file`), access-log nginx пишется в
    stdout;
  - `backend/config/selen.php:18` — `/reset-password/{token}?email={email}`: email и токен попадают в access-log при
    открытии ссылки;
  - `backend/routes/api.php:66` — токен приглашения в пути `GET /api/v1/invitations/{token}`;
  - `docker/php/php.ini` — не задан `zend.exception_ignore_args = On`.
- **Почему это проблема:** IP и email хранятся без срока (у `auth_audit` он есть — 12 месяцев, ADR-0003), в логах
  лежат токены. По 152-ФЗ — хранение без цели и срока.
- **Предложение исправления:**
  - `logging: {driver: json-file, options: {max-size: "10m", max-file: "5"}}` в compose стенда и сервера;
  - формат лога nginx без query string или `access_log off` для `/reset-password/` и `/invitations/`;
  - email в ссылке сброса — вводом на странице;
  - `zend.exception_ignore_args = On`.

  Проверка: `docker inspect --format '{{.HostConfig.LogConfig}}' selen-pm-nginx-1`.

### S-6. Загрузка вложений без лимита частоты и квоты
- **Уровень:** мелочь.
- **Где:**
  - `backend/routes/api.php:155` — нет `throttle`;
  - `backend/app/Http/Requests/Attachments/UploadAttachmentRequest.php:20-25` — до 100 МБ за запрос, загружать может
    любая роль, включая commenter (ADR-0010).
- **Почему это проблема:** участник может заполнить диск Mac mini. Ежечасный бэкап копирует новые файлы в снапшот, и
  место удваивается; встанут PostgreSQL и бэкапы.
- **Предложение исправления:**
  - `RateLimiter::for('uploads')`, например 30 в минуту и N ГБ в сутки на пользователя;
  - предупреждение о свободном месте в `make host-status`.

  Тест: 31-я загрузка за минуту → 429.

### S-7. (частично PR) Гигиена CI
- **Уровень:** мелочь.
- **Где:**
  - `.github/workflows/ci.yml:1-10` — нет блока `permissions`, права токена задаются настройками репозитория;
  - **(PR)** `security.yml` — actions `checkout`, `setup-php`, `setup-node` закреплены тегом, образ gitleaks — тегом
    `v8.30.1`, а не digest.
- **Почему это проблема:** если тег сторонней action или образа передвинут, в CI выполнится чужой код. Сейчас вред
  ограничен: в `security.yml` стоит `contents: read` и нет секретов.
- **Предложение исправления:**
  - `permissions: contents: read` в `ci.yml`;
  - actions — по SHA с комментарием-версией (Dependabot умеет их обновлять);
  - gitleaks — `@sha256:…`.

  В этом PR не исправляется (по заданию PM находки — отдельными задачами).

### S-8. Права уровней бэкапов держатся только на родительском каталоге
- **Уровень:** мелочь.
- **Где:**
  - `scripts/backup.sh:37` — `mkdir -p` не меняет права уже существующих `daily/` и `weekly/` (на Mac mini — 755);
  - `:66` — снапшоты `*.files` с правами вложений 755/644 (осознанно, ADR-0018);
  - `scripts/lib.sh:46` — 700 только у `~/dev/selen-pm-backups`.
- **Почему это проблема:** при переносе каталога (runbook п. 1, `rsync -aH` на флешку и обратно) или ошибке с правами
  родителя дампы и вложения с ПДн станут читаемы всеми локальными пользователями.
- **Предложение исправления:** в `backup.sh` — `chmod 700` для `hourly`/`daily`/`weekly` и каждого `*.files`. Права
  вложений внутри снапшота не трогать.

### S-9. Диск `local` с `serve: true` охватывает вложения
- **Уровень:** мелочь.
- **Где:** `backend/config/filesystems.php:33-45`. Корень диска — `storage/app/private`, `serve => true`; вложения лежат
  внутри (`storage/app/private/attachments`).
- **Почему это проблема:** Laravel регистрирует маршрут `/storage/{path}` с выдачей по подписанной ссылке, и путь
  `attachments/...` им покрыт. Сейчас он недостижим: nginx отдаёт PHP только `/api`, `/sanctum`, `/up`, а подписанных
  ссылок код не делает. Это защита в глубину.
- **Предложение исправления:** `'serve' => false`. Проверка — в `route:list` нет маршрута `storage.local`.

## Принятые риски

- Системный администратор назначает себе роль в любом пространстве; назначение пишется в журнал — ADR-0005.
- Корзина показывает администратору номер, пространство, доску и автора удаления карточек всех пространств, а название —
  только при видимости — ADR-0015.
- Журнал событий всех пространств (id, payload, IP и UA из `auth_audit`) виден системным администраторам — ADR-0003.
- Справочник сотрудников (имя, email) видят системные администраторы и администраторы пространств — ADR-0005.
- Администратор пространства выдаёт доступ любой группе, включая «Все сотрудники» — ADR-0012.
- Вложения любых типов до 100 МБ загружает и commenter, антивируса нет — ADR-0010.
- У dev-базы пароли по умолчанию, порты — только на 127.0.0.1 — ADR-0018.
- Копия бэкапов вне Mac mini отключена до пилота — ADR-0018.
- Доступ к аккаунту claude.ai равен командной строке на Mac mini (Remote Control) — ADR-0018.
- Деактивация не проверяет «последнего администратора», а только предупреждает — ADR-0012.

## Вопросы PM

1. **Tailscale и X-Forwarded-For (к S-1).** Если `tailscale serve` дописывает свой адрес к присланному
   `X-Forwarded-For`, подмена IP работает и из tailnet. Проверка: с MacBook войти на стенд с неверным паролем и
   заголовком `X-Forwarded-For: 10.9.9.9`, затем посмотреть IP в «Журнале событий». После исправления S-1 вопрос
   снимается.
   **Ответ (2026-10-19, LATER-61):** `tailscale serve` заменяет заголовок. Через адрес Tailscale ушло 6 попыток
   входа, каждая с новым `X-Forwarded-For`: 422 ×5, затем 429. Из tailnet подменить IP нельзя было и до исправления.
2. **Кто пишет в пространство LATER.** CLAUDE.md велит сессиям выполнять описание карточки LATER как задание,
   комментарии тоже читаются. Любой, у кого есть право комментировать в LATER, сможет давать инструкции сессиям с
   доступом к командной строке Mac mini. Предложение: держать LATER только личным пространством PM (и QA-бота) и
   записать это в CLAUDE.md.
3. **Email во вкладке «Люди».** Email всех, у кого есть доступ, видят все участники пространства, включая подрядчиков
   «только свои». Если пространство открыто группе «Все сотрудники», каждый сотрудник видит email всех. Это осознанно
   с точки зрения 152-ФЗ?
4. **Mailpit стенда** (`127.0.0.1:8026`, без пароля) хранит ссылки сброса пароля и приглашения. Их может прочитать
   любой процесс на Mac mini, включая сессии Claude. Принимаем до пилота или переводим стенд на SMTP?

Сняты в ходе работы:
- **Dependabot и major.** `ignore` с `update-types` действует только на обычные обновления, не на обновления
  безопасности: так пишут документация GitHub (раздел `allow`) и dependabot-core. Это проверило ревью.
