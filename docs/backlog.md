# Backlog: техдолг и отложенные задачи

Задачи, которые осознанно не вошли в этапы. Когда задача берётся в работу — переносится в промт
этапа и удаляется отсюда. Новые пункты добавляем с источником (этап, отчёт, решение PM).

## Исправленные ошибки

Что было, почему не поймали тесты и чем теперь защищены — чтобы не наступать повторно.

| Ошибка | Причина | Почему не поймали тесты | Исправление и защита |
|---|---|---|---|
| Широкая доска (DEV / «Продукт») прокручивала по горизонтали всю страницу: шапка и кнопки доски уезжали, карточки заезжали под панель дерева, справа оставалась пустая область. С этапа 2a (фасад карточек со сроком и счётчиками) | Скрытые подписи карточек для скринридеров (`sr-only` — «1 комментарий», «Просрочено: срок…») позиционированы абсолютно. Контейнер прокрутки доски не был `relative`, поэтому их точкой отсчёта был корень документа: контейнер их не обрезал, и они растягивали страницу (2503 px при окне 1024 px). Панель дерева (`sticky` + `left-0`) оставалась на месте, а содержимое уезжало под неё. Раскладка (`min-w-0`) была в порядке | Vitest работает в jsdom без раскладки — ширины не считаются. E2E не проверяли ширину страницы, а в их данных карточки без срока, комментариев и чек-листов лежали только в To Do, то есть подписей `sr-only` за краем окна не было. `make perf` (300 карточек) замеряет только время | `relative` у контейнера прокрутки доски (как у `shared/ui/table.tsx`). E2E в `board.spec.ts` (бывший `card-drag.spec.ts`): ширина страницы равна окну, прокручивается только доска, последняя колонка у правого края, панель не перекрывает доску (с панелью и без), перетаскивание к краю прокручивает доску. В E2eSeeder — карточка со сроком в колонке за краем окна |
| Белый экран «Unexpected Application Error! Maximum update depth exceeded» при быстром перетаскивании карточки туда-обратно между соседними колонками (DEV / «Продукт»). С этапа 1 | Целевую ячейку выбирал `closestCorners` — по ближайшим углам прямоугольников карточек, — а `onDragOver` сразу переносил карточку в эту ячейку (setState). Перенос сдвигает карточки обеих колонок; после перемера ближайшей оказывалась карточка прежней колонки → перенос обратно → … Диагностика на демо-доске: сотни переходов Backlog ↔ To Do каждые ~13 мс без движения указателя; когда каскад обновлений из layout-эффекта dnd-kit (`measureRect`) укладывался в один коммит, React упирался в лимит вложенных обновлений. Белый экран — потому что у маршрутов не было своего `errorElement`. Заодно: при отпускании сразу после входа в колонку (переход ещё не отрисован) перемещение терялось | E2E тянули карточку медленно и в пустую колонку — в соседней колонке не было карточек, которые могли бы «перехватить» цель. Vitest (jsdom) раскладку не считает. Ручная проверка — плавными движениями на доске с короткими колонками | Колонку выбирает указатель (вертикальная полоса колонки; дорожка — ближайшая по вертикали), внутри ячейки — ближайшая карточка этой ячейки: сдвиги раскладки цель не меняют. Состояние в `onDragOver` меняется только при смене ячейки; `onDragEnd` учитывает ещё не отрисованный переход. Экран «Что-то пошло не так» вместо белого: `errorElement` маршрутов (внутри каркаса полоса разделов и дерево остаются) и граница ошибок вокруг доски. Защита: E2E на «Плотной доске» (серии махов без пауз; без исправления падает), unit-тесты выбора цели и `onDragEnd`, frontend-тесты экрана ошибки |
| `make backup`, `make restore` и `make pm-backup` / `pm-update` падали в терминале PM: «backup.sh: line 27: DB_DATABASE�: unbound variable». С этапа 0 | bash 3.2 на macOS под UTF-8-локалью (у PM — русская) считает первый байт символа «»» частью имени переменной: `«$DB_DATABASE»` читается как переменная «DB_DATABASE\xc2», которой нет (`set -u`) | Скрипты запускались только из сессии Claude Code, у которой локаль `C`, — там байты не считаются буквами; CI — на Linux с bash 5 | `${DB_DATABASE}»` (и `${stage}»` в `pm.sh`). Защита: `scripts/check-scripts.sh` в `make lint` и CI — переменная вплотную перед не-ASCII символом запрещена; ловушка в CLAUDE.md |
