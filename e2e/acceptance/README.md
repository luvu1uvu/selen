# Приёмочные автотесты (тест-кейс → автотест)

Правило — CLAUDE.md, раздел о процессе («Приёмка подэтапа»). Действует с подэтапа 3c; старые тест-кейсы
задним числом не автоматизируются.

## Где и как

- Файл: `e2e/acceptance/stage-<N>/tc-<этап>.<номер>.spec.ts` — один тест-кейс, один файл.
  Пример: `e2e/acceptance/stage-3/tc-3.23.spec.ts`.
- Тег в названии теста: `@tc-<этап>.<номер>` — по нему тест находит `make e2e-tc TC=3.23`.
- Вход — только сохранённым состоянием: `test.use({ storageState: authFile('e2e-editor@selen.test') })` или
  `pageAs(browser, ...)` из `../../tests/helpers` (вход через форму упрётся в лимит).
- Данные — `E2eSeeder` (не демо-данные): тест-кейс переводится на его пространства и пользователей; не хватает
  данных — дополнить `E2eSeeder` (комментарий: какой тест-кейс их использует).
- Шаги и проверки — как в тест-кейсе: те же действия пользователя, проверяются наблюдаемые признаки из «Ожидаемого
  результата» (роли и подписи, а не CSS-классы).

```ts
import { expect, test } from '@playwright/test'
import { authFile, openBoard, openHome } from '../../tests/helpers'

test.use({ storageState: authFile('e2e-editor@selen.test') })

test('ТК-3.23. Короткое название тест-кейса @tc-3.23', async ({ page }) => {
  await openHome(page)
  await openBoard(page, 'Сквозные тесты', 'Процесс')
  // шаги тест-кейса…
  await expect(page.getByRole('heading', { name: 'Процесс' })).toBeVisible()
})
```

## Запуск

| Команда | Что запускает |
|---|---|
| `make e2e-tc TC=3.23` | автотест одного тест-кейса (несколько — `TC=3.23,3.24`) |
| `make e2e-stage STAGE=3` | все автотесты этапа (`e2e/acceptance/stage-3`) |
| `make e2e` | все E2E, включая приёмочные (так же в CI) |

## Нельзя

- Менять приёмочный тест, чтобы он прошёл. Если тест неверен (а не код) — исправление с объяснением в отчёте PM
  и в комментарии к карточке бага.
- Автотест провалившегося тест-кейса — регрессионный тест бага: падает до исправления, проходит после; ссылка на
  файл — в карточке бага.
- Удобство и внешний вид, которые скриптом надёжно не проверить, не автоматизируются: в отчёте — «только вручную».
